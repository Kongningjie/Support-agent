# 用户回答反馈冻结方案

> 确认日期：2026-10-12；范围：评测体系优化专项批次 1。用户已确认本批次边界，本文及对应实施计划仅授权用户反馈，不授权人工评测或 LLM-as-Judge。

## 目标与边界

登录用户可对本人已成功完成的一次回答提交“有帮助”或“无帮助”，并可更正或删除。反馈是主观质量信号，不等同事实正确，不自动改写知识、模型参数或评测集。不调用在线模型。

以现有 `agent_run.run_id` 为稳定回答标识。只有 `agent_run.user_id` 等于当前用户且 `status=SUCCEEDED` 的运行允许反馈；管理员也不能代替其他用户反馈。会话重置、删除或 Redis 过期不转移反馈归属，已有反馈仍可由本人按运行 ID 管理。前端仅对当前可见、已完成的回答展示反馈入口；会话详情增加该轮 `runId`。

## 反馈契约

| 字段 | 含义和约束 |
|---|---|
| `runId` | 被评价的成功运行 UUID，创建后不可更改 |
| `rating` | `HELPFUL` 有帮助；`NOT_HELPFUL` 无帮助 |
| `reason` | `NOT_HELPFUL` 时必填：`INCORRECT` 内容不正确、`UNSUPPORTED` 缺乏依据、`INCOMPLETE` 不完整、`UNCLEAR` 难理解、`OTHER` 其他；`HELPFUL` 时必须为空 |
| `note` | 用户可选说明，去首尾空白后最多 300 个 Unicode 字符；空白归一为空；拒绝疑似凭据、手机号、身份证号、邮箱及危险控制字符，不进入日志、指标或管理员聚合响应 |
| `version` | 反馈修订版本，首次创建为 0，更正、删除及删除后重建均递增；更正时提交 `expectedVersion`，并发冲突返回 409 |
| `createdAt`、`updatedAt` | 创建及最近更正的 UTC 时间 |

每个 `runId` 最多一条当前反馈。`PUT /api/v1/answer-feedback/{runId}` 创建或覆盖本人反馈：首次创建不传 `expectedVersion`；更正必须传当前版本。重复创建或过期版本返回 409。`GET` 返回本人反馈，未提交返回 404。`DELETE` 必须提交当前版本，立即清空评分、原因和说明，只留不可见的版本标记以防“删除后重建”出现旧请求覆盖新反馈；删除后可重新创建，版本继续递增。非本人或非成功运行统一返回 404，避免泄露存在性。管理员 `GET /api/v1/admin/answer-feedback/summary` 仅返回总数、按 rating 和 reason 的聚合计数，不返回 ID、说明或正文。所有普通接口使用 `ApiResult`，错误保留 HTTP 语义。

MySQL `answer_feedback` 保存反馈事实，唯一约束 `run_id`，不保存回答、Prompt 或用户输入。反馈没有自动过期批次；用户可主动删除，后续若引入保留期须另行确认。前端通过真实 REST 读写，不在本地伪造已提交状态；删除需用户确认。本批次不新增依赖、中间件、角色或模型端口。

## 门禁

Flyway 只追加迁移。后端覆盖成功、非成功/他人运行、输入安全、重复创建、版本冲突和删除；前端覆盖提交、更正、删除及错误状态。执行 `mvn test`、`mvn verify -Pintegration`、前端格式/Lint/类型/单测/构建；可用本地真实后端时执行反馈链路联调，不调用 DashScope。完整 Review 和独立工作记录通过后停止，不自动提交或推送。
