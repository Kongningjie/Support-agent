# Support Agent 冻结方案

## 1. 目录定位

本目录保存各产品期次已经获得用户确认的稳定业务与架构决策，包括已完成期次的回顾性摘要和尚未实施期次的前置冻结方案。冻结方案回答“为什么做、做什么、边界和不变量是什么”；`docs/implementation-plan/` 中的实施计划回答“分几个阶段、每阶段修改什么、如何测试和验收”。

两类文档必须保持分离：

- 冻结方案不得被当作直接开始编码的阶段指令；已完成期次仍以历史实施计划和工作记录作为执行证据。
- 尚未实施的冻结方案确认后，仍须另行编写并确认实施计划，明确阶段编号、依赖、迁移顺序、接口变化和质量门禁。
- 实施计划不得改变冻结方案的业务语义；确需改变时，应先修订冻结方案并取得用户确认。
- 当前系统已经实现的事实仍以 `docs/implementation-plan/10-current-system-baseline.md` 和实际代码、测试为准。

## 2. 分期规则

产品演进按一期、二期、三期、四期分别形成独立冻结方案，不把实施阶段编号当作产品期次：

| 分期 | 定位 | 当前状态 |
|---|---|---|
| 一期 | 核心技术支持、RAG、工单和案例闭环 | 已完成 |
| 二期 | 质量、性能、稳定性与运行准备 | 已完成 |
| 三期 | 用户、会话、长期记忆、账号与 LLM 安全治理 | 已完成；保留两项在线未验证事项 |
| 四期 | 企业知识空间、业务域隔离和范围化检索 | 已完成阶段 18～20 及规定门禁 |

未写入对应期次冻结方案的候选方向不构成范围承诺，也不得据此创建占位接口、字段或代码。
