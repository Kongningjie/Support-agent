# Support Agent 二期质量、性能与稳定性冻结方案

> 状态：已完成；覆盖实施阶段 6～9。详细实验矩阵、门禁和阶段记录保留在历史实施计划中。

## 1. 二期定位

二期不扩展核心业务范围，重点让一期链路具备可重复评测、可解释优化、容量证据和依赖故障恢复能力。优先级冻结为：

```text
回答与检索质量 > 稳定性 > 响应速度 > Token 与基础设施成本
```

质量不合格的方案不能通过更低延迟或成本抵消；参数只能离线比较并经人工确认后修改。

## 2. 冻结范围

- 固化锁定回归集，建立独立优化开发集，防止使用同一批问题反复调参。
- 建立质量、延迟、可靠性、容量和模型用量的统一报告口径。
- 优化中文技术问题、精确术语、同义改写、冲突知识和无知识判断。
- 比较 Chat 模型的完整生产链路质量，最终选择 `qwen3.8-flash`。
- 保留完整答案缓冲、引用和精确值校验，以及最多一次完整重生成。
- 验证 20 个并发会话、持续 2 RPS、短时 5 RPS 的冻结容量目标。
- 补强模型、MySQL、Redis、Elasticsearch 和异步任务的超时、重试、恢复与资源释放。
- 动态评测报告写入 `target/`，不进入 Git，不保存完整 Prompt、知识正文或模型输出。

## 3. 质量和运行不变量

- 锁定回归集不得为提高分数修改标注或增加单条特判。
- 生产默认检索模式必须满足 Recall、MRR、nDCG、无命中和精确词等冻结门槛。
- 检索依赖故障不得解释为“没有知识”。
- 在线测试必须单独获得真实密钥、网络和 Token 预算授权。
- 不实施线上自动调参、自学习、备用模型供应商或以新中间件代替证据不足的优化。
- 新依赖、数据表、公共接口或业务流程必须另行确认。
