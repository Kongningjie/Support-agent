日期：2026-10-17。状态：用户已确认采用断连取消，本文件记录稳定设计边界；实现进度以下方增量和独立实施计划为准，不是直接开始编码的指令。

2026-11-02 执行增量：依据[单批次实施计划](../implementation-plan/18-chat-disconnect-cancellation-implementation-plan.md)仅授权并实现步骤一的 SSE 生命周期与发送队列补强；整体目标尚未完成，模型主动取消仍待后续步骤。原冻结决策继续有效。

2026-11-02 后续增量：用户授权步骤二，并确认以 SDK HttpTransport 扩展补齐默认传输的取消阻塞问题。步骤二已实现和验证 Chat/Intent/工单 Agent 模型取消；全面业务检查、提交核实与重放治理仍未执行。该增量不承诺供应商停止计费，不引入额外依赖或更换 SDK。

## 1. 目标与当前差距

2026-11-02 步骤三增量：已完成业务阶段和发送边界取消检查、重生成阻断、独立释放与失败审计，以及已提交成功保护；真实 HTTP/SSE 与 Redis/MySQL 联动清理通过。提交原子协调、响应不确定核实及重放/前端治理仍未执行，详见[步骤三记录](../work-logs/2026-11-02-chat-business-cancellation-step-three.md)。下述差距为冻结时基线，最新实现以执行增量和[当前系统基线](../implementation-plan/10-current-system-baseline.md)为准。

当前 SSE 已有发送失败、超时、心跳和慢客户端保护，失败发送不会提交未完成轮次；但发送通道关闭不会主动取消正在等待的模型调用。模型仍可能继续生成，甚至因输出校验失败而重生成。

本次目标：后端检测到断连后，通知业务停止后续步骤，取消模型流订阅并释放该请求的上游 HTTP 资源，禁止重生成，及时清理运行占用；同时保留已完成结果的幂等重放。

后端无法可靠区分关闭页面与短暂断网。本方案统一在检测到断连后取消，不设置重连宽限窗口。现有心跳周期为 15 秒，断连感知并非即时。取消本地请求不构成供应商立即停止推理或停止计费的保证。

## 2. 范围与不变量

- 沿用六模块、AgentScope、DashScope、Redis 和现有 SSE 协议，不增加模块、中间件、依赖、数据库业务状态或外部取消接口。
- 覆盖聊天入口及问候、知识问答、工单 Agent 三个模型回答分支；不扩展 Judge、后台案例草稿等独立任务的取消语义。
- 保留完整答案安全校验后才发送正文的策略，不向客户端发送原始模型 delta。
- 不做 SSE 断点续传、事件持久化日志、后台持续生成或服务重启后的推理恢复。
- 取消不是模型故障；不得触发模型重试、意图故障降级后继续执行或答案重生成。
- 已经执行中的其他依赖操作不承诺全部立即中断；必须在返回后检查取消，不再开始下一步骤。聊天链路上的模型订阅必须支持主动取消，其他同步模型步骤也须审计取消传播与降级行为。

## 3. 请求级取消控制

应用层定义不依赖 Spring、Reactor 或 AgentScope 的请求级控制对象，由接口层创建，沿本次聊天传入用例和模型适配层。

| 概念 | 含义与约束 |
|---|---|
| 取消标记 | 仅影响当前请求，记录首次终止原因；重复通知幂等 |
| 取消检查 | 在阶段边界检查，已取消则以专用内部异常退出，不进入普通故障重试路径 |
| 取消动作注册 | 当前模型调用注册终止订阅和释放请求资源的动作；先取消后注册时，动作仍须立即执行 |
| 注册清理 | 调用结束注销动作；单个动作异常不能阻断其他清理 |
| 最终提交门闩 | 原子协调取消与最终提交，仅用于内存执行控制，不新增数据库状态 |

不通过全局布尔变量或共享线程中断状态串扰其他请求。不仅依赖业务线程中断或首 Token 回调发现取消；模型尚未返回首 Token 时也必须能够取消。

## 4. SSE 与业务流程

连接错误、响应超时、心跳或业务事件写入失败、慢客户端保护，以及非正常完成回调，均通知取消。正常完成仅释放资源，不能误判取消。回调只做快速通知与资源中止，不直接执行数据库清理。

关闭发送通道时停止心跳、拒绝后续事件、唤醒发送线程，并让待发送事件立即失败，不能只设置 closed 标志后留下等待线程。业务尚未启动时已断连也必须进入清理，避免已取得运行权却无人释放。

业务在上下文加载、意图识别、检索、模型调用前后，以及安全校验、重生成、每段正文发送、最终提交前检查取消。收到取消后不再发送 error，不再提交半轮会话，不启动成功后的摘要更新或长期记忆候选生成。

模型调用期间不持有数据库事务或最终提交门闩。模型正常超时继续保留为兜底，不能替代主动取消。

## 5. 模型与上游请求取消

适配层把请求级取消连接到实际订阅；取消后立即终止本地等待、取消模型订阅并释放本请求 HTTP 响应资源。不得关闭供其他请求共享的 HTTP 客户端。

工单 Agent 同时终止本次 Agent 执行，禁止后续推理和工具调用，释放本次 Agent 资源。取消异常穿过适配层时保留取消语义，不得统一包装成 CHAT_MODEL_UNAVAILABLE。

必须通过本地可控流式 HTTP 服务验证当前 AgentScope 版本的取消确实传播到传输层，不能把业务线程退出当作上游连接关闭的证据。如果 SDK 不传播取消，应先明确适配补齐方案；若需要变更依赖或技术栈，暂停并再次确认。

## 6. 运行清理与提交竞争

沿用现有会话失败清理及审计终态，不新增 CANCELLED 数据库状态。拟记录以下低基数终止原因；它们不是新增 SSE 事件或对外响应字段：

| 原因 | 含义 |
|---|---|
| CHAT_CLIENT_DISCONNECTED | 连接错误、异常完成或发送失败导致终止 |
| CHAT_RESPONSE_TIMEOUT | SSE 响应生命周期超时 |
| CHAT_CLIENT_TOO_SLOW | 发送队列或写入确认触发慢客户端保护 |

清理绑定所有者、会话和 runId；runId 表示一次执行尝试，不能清理或续租后续新运行。未提交结果不得保存正文片段、完整轮次或 Agent 状态。旧调用迟到返回时仍不得提交。各项清理独立尝试、可重复执行；持久化不可用时记录安全告警，保留现有租约恢复兜底，不能宣称占用已释放。

取消先取得执行权则禁止提交；提交先进入不可取消的最终短区间则允许提交收尾。最终短区间不得包含模型调用、客户端写入或其他长操作。成功与取消审计不能互相覆盖。提交响应不确定时不得盲目写失败，须按相同 runId 与已保存消息结果核实；无法核实时记录未知并依赖幂等恢复，不猜测提交结果。

## 7. 幂等、重试与结果重放

| 情况 | 状态处理 | 再次请求的行为 |
|---|---|---|
| 生成中断连，未提交 | 取消、释放运行占用、标记失败 | 用户显式重试相同 clientMessageId，使用新 runId 重新执行 |
| 已提交但完成事件未送达 | 保留已完成结果 | 重放原答案，不调用模型 |
| 已开始最终提交 | 按提交门闩结果处理 | 依据最终已保存结果决定重放或重新执行 |
| 正在重放时断连 | 停止本次发送，不修改原结果 | 原结果仍可重放 |
| 旧运行尚未完成清理 | 保持运行互斥 | 返回现有忙语义，不并行启动第二次执行 |

clientMessageId 表示同一条用户消息，不等于执行尝试；相同 ID、不同内容仍必须拒绝。重放先校验身份、空间权限、会话存在性、当前代际及消息内容，已完成消息可在客户端持旧会话版本时重放；仅新执行严格检查 expectedVersion。当前 Redis begin 先检查版本再查完成消息的顺序需要调整并增加回归测试，不得借此放宽新执行或跨代际限制。

结果重放重新发送完整安全答案，不按旧事件序号接续；不得重复写会话、更新摘要、生成长期记忆候选或新建工单建议。前端重试复用消息 ID，替换对应临时正文而非重复追加；恢复后仍须遵守现有权限复核。

首次请求若连 conversation.started 都未收到，客户端可能没有服务端分配的 conversationId，不能保证依靠 clientMessageId 找回结果。本批次不新增全局消息定位或浏览器刷新后的自动恢复机制。会话过期、删除或重置后，仍遵守原有生命周期和代际隔离规则。

## 8. 验证与后续执行

单批次实施计划须明确接口内部签名调整、取消传播、提交协调、Redis 幂等顺序修正、必要的前端兼容以及低基数取消指标。日志不得包含问题正文、Prompt、完整模型输出或密钥；无法取得完整 Token 用量时明确未知，不能把取消请求当作零成本。

验收至少覆盖：首 Token 前取消、流中取消、先取消后注册、重复取消、重生成前取消、正常完成、未启动先断连、工单 Agent 后续工具阻断、队列与线程释放、多请求隔离、旧运行迟到、取消与提交竞争、提交响应不确定、旧版本已完成重放、未完成重试、内容冲突、权限变化、代际隔离及重放再次断连。

使用本地可控 HTTP 流服务验证订阅取消和上游连接终止，使用真实 SSE 客户端断开验证状态清理；不以服务端自行抛异常代替全部链路验证。不承诺供应商侧停止推理。默认不读取真实密钥、不运行在线模型测试。

实施完成须执行 mvn test、mvn verify -Pintegration；如修改前端则执行规定前端质量门禁与相关真实后端联调。完整 Review 后记录实际命令、结果、清理时效和未验证事项，不自动提交或推送。
