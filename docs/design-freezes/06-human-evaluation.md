# 人工评测冻结方案

> 确认日期：2026-10-12；范围：评测体系优化专项批次 2。用户确认人工评测及受限反馈候选列表。本批次不执行 LLM-as-Judge，不自动调用在线模型。

## 目标和样本边界

把固定回答用例和 `NOT_HELPFUL` 反馈作为候选线索，由管理员显式创建已脱敏的评测副本。固定用例以现有 30 条回答用例 ID 为来源；反馈候选列表只暴露 `runId`、会话 ID、原因和时间，不暴露用户 ID、说明或正文。管理员可通过既有会话详情权限查看尚未过期的回答，但不得自动复制会话内容。会话过期、重置或删除后不补造样本。创建时管理员必须逐项确认问题、答案、允许展示的证据均已脱敏；服务端再次拒绝疑似凭据、手机号、身份证和邮箱。评测表只存脱敏副本，不存反馈说明或原始完整 Prompt。

评测副本关联来源类型 `FIXED` / `FEEDBACK`、来源标识、知识空间和创建人；同一来源只能创建一份。反馈来源必须仍为有效的 `NOT_HELPFUL` 成功运行；固定来源必须是现有冻结数据集中的用例。跨空间样本只允许平台 `ADMIN` 访问；不能把空间成员身份当作评审权限。脱敏副本独立于原反馈，原反馈删除后不回填。评测副本在本批次不自动过期，后续留存/清理策略需另行冻结。

## 评审与量表

五维均使用整数 0～2：事实正确、引用支持、完整性、可操作性、表达清晰度。0 为明显不满足，1 为部分满足或依据不足，2 为满足；提交时填写一段覆盖五维的理由。对没有引用义务的样本，引用支持评 2 且说明“不适用”，不得遗漏维度。第一、第二评分必须由两个不同管理员独立提交，提交前互不可见且不可修改。若任一维分数不同，进入分歧复核，第三位不同管理员独立给出五维最终评分和理由；若完全相同，自动形成一致结论。管理员不能自己完成两个角色。

硬规则（权限、引用合法性、敏感信息、精确值）仍由原有确定性门禁判定，人工评分不能覆盖。结论形成后可由管理员明确加入独立开发集；从开发集晋升回归集须另一次显式审批。每次晋升记录操作者、UTC 时间、动作和单调递增数据集版本。回归集与阶段 8/17/20 固定集隔离，不自动改变现有回归测试或发布门禁。

本批次的样本副本和已提交评分不可编辑；若发现误脱敏或误评分，不得在数据库中直接覆盖。撤销、修订和重标注需另行冻结流程，本批次不把有争议样本晋升数据集。

## 权限、审计和验收

只有 `ADMIN` 可看候选、创建样本、评分、复核、晋升及查看结论。普通用户不能读取任何评测副本。评审前只能看到自己的评分，不能通过列表、详情或错误消息推断另一位评分。所有写入使用 MySQL 原子约束和状态检查；来源、评审人、晋升动作留痕，不把正文写入普通日志、指标或工作记录。提供管理员真实前端页面，显示待评审、待复核、开发集和回归集，并明确表单字段含义。测试至少覆盖两人隔离、同人重复、分歧、复核、晋升审批、脱敏和权限；执行后端单元/集成及前端质量门禁，完成完整 Review 和工作记录后停止，不自动提交或推送。
