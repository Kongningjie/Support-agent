# Support Agent 三期用户、记忆与 LLM 安全治理冻结方案

> 状态：已完成；覆盖实施阶段 10～17 及阶段 13 补强批次。阶段 10 真实在线摘要质量评测与阶段 17 真实模型对抗验证仍为未验证项。

## 1. 三期定位

三期在一期业务闭环和二期质量基线上补齐“谁在使用、资源属于谁、跨会话保留什么、模型输入输出如何失败关闭”四类治理能力。三期分为两个连续实施批次：

1. 阶段 10～14：单会话上下文、用户认证、资源归属、会话生命周期、用户可控长期记忆和账号安全。
2. 阶段 15～17：Prompt 信任边界、统一模型输出安全网关、安全评测与低基数可观测性。

第二批次是三期安全补强，不再单独占用产品第四期编号。

## 2. 身份与资源归属

- 使用本地用户名密码、BCrypt 和 Redis 不透明 Bearer Token。
- 角色固定为 `USER`、`ADMIN`，不实现复杂 RBAC。
- 普通用户只能访问自己的会话、工单和长期记忆；管理员治理用户和知识并查看全部工单。
- 会话与工单绑定公开用户 UUID，历史无归属数据不得由首个访问者自动接管。
- 支持强制改密、登录递增退避、临时锁定、Token 数量上限、撤销和安全事件审计。
- 保留 `AuthenticationPort` 与外部主体映射边界，但不接入真实 OIDC/SSO。

## 3. 会话与长期记忆

- 会话使用 Token 预算、最近完整轮次和结构化滚动摘要，不再简单删除旧轮次。
- 摘要必须通过 Schema、版本、来源实体和 Redis CAS 校验，提交成功后才能裁剪旧轮次。
- 会话支持列表、详情、重置和删除，并校验所有者、版本与运行状态。
- 长期记忆默认关闭，模型只生成 `PROPOSED` 候选，用户确认后才成为 `ACTIVE`。
- 个人记忆类型为 `PREFERENCE`、`CONSTRAINT`、`ENVIRONMENT`，用户可以更正、撤销和永久删除。
- 候选生成限流和失败不得影响正常聊天；未确认候选按冻结规则清理。

## 4. LLM 安全治理

- 当前消息、历史、摘要、长期记忆、检索证据和工单字段统一视为不可信数据。
- 输入使用 `ALLOW`、`GUARD`、`BLOCK` 三级判定；高风险上下文只从本次调用排除，不自动删除来源。
- 问候、RAG、工单回答、工单草稿和案例草稿统一经过发送前或持久化前输出安全网关。
- 输出动作固定为 `PASS`、`REGENERATE`、`REJECT`，未通过正文不得发送或持久化。
- 每次受保护模型调用使用只存在于内存的随机泄漏标记。
- 固定中文安全数据集与低基数指标验证直接注入、间接注入、输出泄漏和困难正常样本。
- 确定性安全策略故障必须失败关闭，不因安全检查异常放行正文。

## 5. 三期不变量

- 不保存密码、原始 Token、Token 哈希、完整 Prompt、隐藏推理或模型完整响应。
- 个人长期记忆必须由本人控制，不能自动成为企业共享知识。
- 认证和所有权校验必须进入应用层，不能只依赖前端、URL 或 Controller。
- 安全指标禁止使用用户、会话、文档、工单或正文等高基数和敏感标签。
- 离线确定性评测不能表述为真实模型开放世界攻击防御率。
- 三期不实现多租户、组织架构、真实 SSO、外部授权服务器或复杂 RBAC。

阶段 10～17 已完成三期规定离线与集成门禁。阶段 10 真实在线摘要质量评测按用户决定暂缓；阶段 17 真实模型对抗验证未获单独授权。两项均不得被误写为已通过。
