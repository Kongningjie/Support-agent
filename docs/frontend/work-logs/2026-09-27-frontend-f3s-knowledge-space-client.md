## 目标与边界

- 让现有 Chat、会话和手工工单正式客户端显式选择并展示知识空间。
- 使用阶段 19 已完成的真实后端接口，不新增后端业务状态、角色或权限语义。
- 会话建议工单只继承服务端冻结空间，客户端不得提供覆盖字段。
- 不实现 F4 的空间治理、知识、案例、任务或评测页面，不提前执行后端阶段 20。

## 实施内容

- 新增知识空间只读 API、分页聚合、稳定 TypeScript 类型和可复用选择组件；管理员响应中的 `DISABLED` 空间也会在客户端选择集合中排除。
- 新会话必须显式选择空间，既有会话从服务端恢复并锁定当前代际空间；SSE 请求和引用类型均携带 `spaceId`。
- 会话重置显式提交目标空间，并在对话框中说明会清除轮次、摘要、建议和消息幂等状态。
- 手工工单必须显式选择空间；会话建议建单保持服务端继承语义，不新增可伪造空间字段。
- 会话列表、工单列表、工单详情和引用补充空间标识或最小空间摘要展示。
- 更新前端冻结计划、当前系统基线和前端 README；后端阶段 20 仍未启动。

## 真实本地联调

- 复用健康的 MySQL、Redis、Elasticsearch 容器，并以本次进程临时覆盖正确的 MySQL 映射端口启动真实 Spring Boot 后端；未修改或提交 `.env`。
- 通过 Vite `/api` 代理登录临时本地测试用户，真实读取 1 个可用 `GLOBAL` 空间；新会话页面初始不自动选择，选择后才能发送。
- 使用显式 `GLOBAL` 创建会话并成功提交一轮；既有会话的空间选择被锁定。随后通过真实重置接口确认 `generation=1`、`version=0`、`spaceId=GLOBAL`，刷新页面后旧轮次已清空且空间仍锁定。
- 使用显式 `GLOBAL` 创建工单草稿 `T000000000003`，详情页正确展示“企业公共空间（GLOBAL）”。
- 联调结束后清除了临时账号、Token、会话、工单、运行轨迹、幂等和安全测试数据；现有用户密码和业务数据未修改。
