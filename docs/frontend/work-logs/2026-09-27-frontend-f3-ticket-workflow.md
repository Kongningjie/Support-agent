## 目标、验收与范围

- 目标：基于既有真实工单 API，实现列表、详情、手工草稿、会话建议草稿及既有状态流转。
- 修改范围：`support-agent-web/`、前端阶段计划状态、当前系统基线和本记录。
- 状态边界：`DRAFT` 可编辑、提交或关闭；`OPEN` 可解决或关闭；`RESOLVED` 与 `CLOSED` 只读。
- 一致性边界：写操作以服务端版本为事实，创建、提交、解决和关闭使用浏览器生成且可复用的幂等键；409 时保留用户输入。
- 权限边界：普通用户与管理员使用同一页面，页面只展示后端返回的数据，不推断或扩展资源范围。
- 不实现：指派、评论、附件、SLA、优先级、通知、管理员案例治理、任务治理或任何 F4 能力。
- 开始时 Git 状态：`main` 与 `origin/main` 一致，工作区干净。

## 实施内容

- 新增工单 REST 类型与适配器，覆盖分页查询、详情、手工草稿、会话建议草稿、修改、提交、解决和关闭。
- 新增工单列表与详情页面，提供状态/关键词筛选、分页、字段说明、状态受控按钮和本地时区展示。
- 对创建、提交、解决和关闭使用浏览器 UUID 幂等键；失败重试保留原 Key，成功后才清除。
- 409 冲突保留编辑、解决或关闭表单，并允许刷新最新服务端版本后继续操作。
- 将 F2 的 `ticket.suggested` 接入真实建议建单；修复同一会话 URL 同步导致 SSE 建议被 REST 详情覆盖的问题。
- 注册 Element Plus `ElDialog`，使手工建单、解决和关闭表单使用真实对话框；补充侧边导航、路由和工单页面样式。
- 更新前端计划、当前系统基线和 README，只记录 F3 已交付能力，未提前实现 F4。

## 真实联调证据

- 后端 readiness 中 MySQL、Redis、Elasticsearch 和 DashScope 均为可用状态；前端通过 Vite `/api` 代理连接真实后端。
- 手工路径：创建 `T000000000001`，修改草稿后关闭，最终状态 `CLOSED`、版本 2。
- AI 路径：真实 DashScope 无可靠知识回答产生 `ticket.suggested`，创建 `T000000000002`，随后完成 `DRAFT → OPEN → RESOLVED`，最终版本 4。
- 并发冲突：在草稿编辑期间推进服务端版本，保存得到 409；页面保留未提交标题，刷新到最新版本后成功保存。
- 异步闭环：`T000000000002` 对应 `CASE_GENERATION` 任务状态为 `SUCCEEDED`，执行 1 次，并生成 1 条 `resolved_case`。
- 列表验收：管理员可看到两张真实工单；按 `CLOSED` 筛选后只返回 `T000000000001`，总数和分页信息正确。
