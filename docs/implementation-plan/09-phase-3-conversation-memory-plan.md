# Support Agent 三期用户与记忆治理实施计划

> 版本：2.1；冻结日期：2026-09-20；状态：阶段 10 已完成离线门禁且真实在线评测暂缓；阶段 11～13 已完成全部规定离线与集成门禁；阶段 14 等待执行。

## 1. 文档目的

本文是三期阶段 10～14 的唯一实施依据。阶段 10 优化单个 Redis 会话内的上下文管理；阶段 11～14 依次建立本地用户认证、资源归属、会话生命周期、受用户控制的长期记忆以及账号安全与未来 SSO 迁移边界。

执行前必须同时阅读一期总计划、二期优化计划、`docs/standards/` 和最近一份阶段工作记录。每次只能执行一个阶段；未收到用户对相应阶段的明确执行指令前，不得修改该阶段业务代码。

## 2. 当前基线与问题

当前会话机制具有以下行为：

- Redis 只保留最近 20 个成功轮次；更早轮次直接删除，不生成摘要。
- 模型实际最多读取最近 6 轮，并受 12,000 字符上限约束。
- 失败或中断轮次不写入会话；会话空闲 TTL 为 7 天。
- 意图识别和普通 Chat 使用最近上下文；AgentScope 不透明状态虽可写入 Redis，但不会恢复，不属于有效的跨请求记忆。
- MySQL 审计摘要、工单、知识文档和已解决案例不是会话记忆，不得混入本阶段的摘要存储。

直接淘汰旧轮次会丢失早期目标、已确认决策、约束和未解决问题；按字符截断也无法稳定控制不同中英文内容的模型输入成本。

## 3. 阶段范围

阶段 10 仅交付以下四项能力：

1. 单会话滚动摘要。
2. 模型输入 Token 预算与上下文组装。
3. 摘要生成、提交和旧轮次裁剪的并发安全。
4. 固定中文摘要质量评测与报告。

本阶段明确不实现：

- 跨会话长期记忆、用户画像、偏好学习或相似历史会话召回。
- 会话删除、重置、列表、详情或新的公共管理 API。
- 认证授权、多租户、组织和用户身份绑定。
- MySQL 摘要表、向量化会话记忆、Elasticsearch 会话索引。
- RocketMQ、其他消息队列、新模块或新的模型供应商。
- AgentScope 不透明状态恢复或跨请求工具执行轨迹复用。

## 4. 冻结架构

### 4.1 应用层职责

在 `support-agent-application` 中建立独立的 `ConversationContextService`，统一负责：

- 读取当前结构化摘要和未被摘要覆盖的完整轮次。
- 估算各上下文分区的 Token 数。
- 判断软触发、硬触发和无需压缩三种情况。
- 按固定优先级组装提供给意图识别、查询改写和回答模型的上下文。
- 发起摘要任务，但不直接依赖 Redis、DashScope 或 AgentScope。

摘要模型必须通过独立的 `ConversationSummaryPort` 调用，模型固定为 `qwen3.7-flash`。不得把摘要能力合并到 Chat、Intent、Embedding 或 Rerank 端口。

### 4.2 基础设施职责

Redis 继续作为单会话记忆的唯一存储。会话摘要与完整轮次使用相同的 7 天空闲 TTL，不新增数据库表。

正常回答提交后，使用应用内受控异步执行器进行尽力摘要；不写 Outbox、不引入消息队列。应用重启导致异步任务丢失时保留原始轮次，由下一次请求重新判断并触发。达到硬阈值时必须在当前请求内同步完成摘要，失败则安全终止本次请求，不得删除任何尚未成功覆盖的原始轮次。

### 4.3 上下文消费者

结构化摘要和最近完整轮次必须通过同一个上下文组装结果提供给：

- 意图识别与独立查询改写。
- 问候回答。
- 有依据的 RAG 回答。
- 工单只读 Agent 的用户上下文。

工单 Agent 仍只能读取当前识别出的唯一工单号。历史中的其他工单号不得扩大工具权限。

## 5. 结构化摘要契约

摘要必须使用稳定 JSON Schema，禁止保存模型自由文本作为正式摘要。字段定义如下：

| 字段 | 含义 | 约束 |
|---|---|---|
| `schemaVersion` | 摘要结构版本 | 固定稳定字符串；结构变化必须显式迁移 |
| `summaryVersion` | 当前摘要修订版本 | 从 1 递增，用于 CAS |
| `coveredThroughVersion` | 摘要已经覆盖到的会话成功版本 | 只能前进，不能回退 |
| `goals` | 用户当前仍有效的目标 | 去重后的字符串数组，不保留已明确取消的目标 |
| `confirmedDecisions` | 会话中已经确认且仍有效的决定 | 必须优先保留最新决定 |
| `constraints` | 技术、业务、安全和输出约束 | 不得把模型建议误记为用户确认 |
| `unresolvedQuestions` | 尚未解决或等待用户确认的问题 | 问题解决后必须从后续摘要移除 |
| `keyEntities` | 错误码、版本、命令、配置键、路径、工单号、类或包、URL 等关键实体 | 每项包含类型、规范值和来源轮次版本 |

摘要不得保存隐藏推理、模型内部状态、完整 Prompt、知识正文、供应商原始响应或已被安全规则禁止的敏感凭据。

关键实体沿用一期八类精确词定义。摘要中的关键实体必须是源轮次确定性提取结果的子集；出现无来源实体时整份候选摘要作废，不允许只删除单个错误字段后继续使用。

## 6. Token 预算与压缩规则

### 6.1 确定性 Token 估算

本阶段不新增分词或 Tokenizer 依赖。使用确定性保守估算器：

- CJK 字符按每字符 1 Token 估算。
- 连续非 CJK 内容按每 4 个字符 1 Token 向上取整。
- 换行、角色标记和 JSON 结构计入估算。
- 汇总结果增加 15% 安全余量并向上取整。

估算值用于预算和触发判断；真实供应商 usage 继续用于评测报告，不反向自动修改线上配置。

### 6.2 初始冻结参数

| 参数 | 初始值 | 含义 |
|---|---:|---|
| `inputBudgetTokens` | 24,000 | 单次 Chat 输入的内部工程预算，不代表供应商最大窗口 |
| `outputReserveTokens` | 1,200 | 为正式回答预留的最大输出空间 |
| `safetyMarginTokens` | 1,024 | 应对估算误差和协议开销的固定余量 |
| `recentFullTurns` | 6 | 始终优先保留的最近完整成功轮次 |
| `softTriggerTurns` | 12 | 达到该轮次数后，在回答成功后异步压缩 |
| `softTriggerMemoryTokens` | 6,000 | 会话摘要与完整历史达到该估算值后异步压缩 |
| `hardTriggerTurns` | 20 | 达到现有原始轮次上限时，下次模型调用前同步压缩 |
| `summaryMaxOutputTokens` | 1,200 | 单次结构化摘要的最大输出 Token |

以上参数必须配置化并在启动时校验：所有数值必须为正；`recentFullTurns < softTriggerTurns <= hardTriggerTurns`；固定预算、输出预留和安全余量不得耗尽输入预算。

### 6.3 上下文优先级

上下文按以下优先级组装，低优先级内容不得挤占高优先级内容：

1. 系统安全规则和输出契约，不得截断。
2. 当前用户问题，不得截断。
3. 当前检索证据或唯一允许的工单工具边界，不得从正文中间截断。
4. 结构化滚动摘要，用于保留较早目标、决定和约束。
5. 最近 6 个完整轮次，从新到旧纳入。

若固定内容、当前问题、证据、输出预留和安全余量已经超过预算，必须返回明确的安全错误，不得静默删除安全规则、证据或当前问题。摘要用于替代较早历史，不得替代当前 RAG 证据。

### 6.4 滚动压缩

- 软阈值满足任一条件即触发异步摘要：成功轮次达到 12，或会话记忆估算达到 6,000 Token。
- 摘要覆盖尽可能多的较早轮次，但必须保留最近 6 个完整轮次。
- 已有摘要时，新摘要输入为“当前结构化摘要 + 新增待覆盖轮次”，而不是重新发送全部历史。
- 达到 20 轮或组装结果即将超过输入预算时，在调用意图或回答模型前同步摘要。
- 只有新摘要原子提交成功后，才能裁剪它已经覆盖的旧轮次。
- 摘要失败、超时、结构不合法、实体校验失败或 CAS 失败时，不得删除原始轮次。

## 7. 并发与一致性

摘要快照必须携带：会话 ID、预期摘要版本、目标覆盖版本及源轮次版本集合。Redis 适配器使用单次原子操作完成以下判断和修改：

1. 当前摘要版本等于任务读取时的预期版本。
2. `coveredThroughVersion` 没有被其他任务推进到更高位置。
3. 候选摘要的目标覆盖版本不超过当前会话成功版本。
4. 写入新摘要并递增 `summaryVersion`。
5. 仅裁剪版本小于或等于新 `coveredThroughVersion` 的轮次，同时完整保留更新的轮次和最近 6 轮。
6. 同步刷新摘要、轮次和会话键的 TTL。

异步摘要期间允许新一轮聊天继续完成。先完成 CAS 的摘要生效，失败任务必须丢弃候选结果并重新读取，不得覆盖较新摘要。不得使用 JVM 本地锁代替 Redis 原子一致性。

同一候选摘要最多调用模型两次：第一次失败仅在错误属于超时、限流或临时供应商故障时执行一次有限重试；Schema、实体越界和确定性校验失败不以相同输入盲目重试。同步硬阈值摘要最终失败时，本次聊天返回依赖错误，客户端不会收到半成品回答。

## 8. 摘要质量评测

### 8.1 固定数据集

建立 40 条自编中文多轮会话作为唯一阶段验收集，不引入公开数据集：

- 8 条指代、省略和追问。
- 8 条目标、已确认决策和约束保持。
- 8 条错误码、版本、命令、配置、路径和工单号等精确实体。
- 6 条用户纠正旧信息或推翻旧决定。
- 6 条长对话、多次滚动摘要。
- 4 条模型失败、Schema 错误、实体幻觉和并发 CAS 冲突。

数据必须固定版本与 SHA-256，使用稳定 `caseId`，区分开发集和锁定回归集。不得根据锁定用例增加硬编码特判。

### 8.2 报告指标

报告至少包含：Git 提交、数据集版本与哈希、摘要模型、参数快照、运行时间、原始估算 Token、摘要后估算 Token、真实在线 usage、压缩耗时、重试次数、CAS 结果和以下质量指标：

- JSON Schema 通过率。
- 关键实体召回率和无来源实体数量。
- 目标、决定、约束和未解问题保留率。
- 最新纠正覆盖旧信息的准确率。
- 压缩前后意图、独立查询和最终回答一致性。
- 单次及多次滚动后的 Token 降幅。

动态评测报告写入模块 `target/`，不得提交到 Git；冻结数据集和评测代码必须纳入版本管理。

### 8.3 验收门禁

- 40 条用例的摘要 Schema 通过率为 100%。
- 八类关键实体召回率为 100%，无来源实体数量为 0。
- 用户最新纠正、已确认决定和硬约束保留率为 100%。
- 指代、独立查询和最终回答的端到端通过率不低于 95%，且安全用例不得退化。
- 可压缩用例的会话记忆估算 Token 中位降幅不低于 30%。
- CAS 竞争、异步任务丢失、Redis TTL 和硬阈值失败测试全部通过，未发生未覆盖轮次丢失。
- 不记录或输出完整会话、摘要正文、模型原始响应和密钥。

## 9. 测试与完成门禁

阶段 10 至少执行：

```powershell
mvn test

mvn verify -Ponline-test
```

真实摘要模型测试必须获得用户对密钥、网络和 Token 预算的明确授权。若未授权，阶段不得宣称在线摘要质量门禁已经通过。

完成前必须：

- 更新阶段工作记录，逐项写明字段、配置、并发行为、测试结果和未验证项。
- Review 全部代码、配置、Redis 原子脚本、评测数据和文档差异。
- 执行敏感信息扫描并确认 `.env`、动态报告和模型正文未进入 Git。
- 只完成阶段 10，不开始长期记忆、会话管理或其他后续优化。
- 不自动提交或推送，等待用户确认。

## 12. 阶段 11：用户、认证与资源归属

### 12.1 范围和技术选择

- 用户名和密码保存在本地 MySQL，密码只保存 BCrypt 哈希。
- 阶段 11 使用 Spring Boot 管理版本的 Spring Security：接口层通过 `SecurityFilterChain` 认证 Bearer Token，基础设施层通过 `BCryptPasswordEncoder` 处理密码；不引入 OAuth2、OIDC 或第三方身份 SDK。
- 登录成功返回随机不透明 Bearer Token；原始 Token 只返回一次，服务端仅在 Redis 保存 SHA-256，不使用 JWT。
- Token 固定有效期 2 小时，不滑动续期，不提供 Refresh Token；重新登录获得新 Token。
- 角色仅允许 `USER`、`ADMIN`；状态仅允许 `ACTIVE`、`DISABLED`。
- 仅管理员创建用户，不开放注册、邮箱、短信、找回密码、组织、多租户或第三方登录。
- 不新增 Maven 模块。用户领域、用例、持久化、接口和装配分别进入现有分层模块。

### 12.2 `app_user` 字段

| 字段 | 含义 | 约束 |
|---|---|---|
| `id` | MySQL 内部自增主键 | 不通过 API 暴露 |
| `user_id` | 用户公开 UUID | `BINARY(16)`、唯一、创建后不可变 |
| `username` | 登录用户名 | 3～64 位，规范化为小写；仅允许字母开头及字母、数字、点、下划线、短横线；唯一 |
| `display_name` | 页面或审计展示名称 | 1～100 字符，不参与登录 |
| `password_hash` | BCrypt 密码哈希 | 不得出现在响应、日志或审计明细中 |
| `role` | 用户角色 | `USER` 或 `ADMIN` |
| `status` | 账号状态 | `ACTIVE` 或 `DISABLED`；禁用时撤销全部 Token |
| `version` | 乐观锁版本 | 更新角色、状态时递增 |
| `password_changed_at` | 最近一次密码建立或变更时间 | UTC，阶段 14 用于令牌治理 |
| `created_by` / `created_at` | 创建人和创建时间 | 初始管理员由 `SYSTEM_BOOTSTRAP` 创建 |
| `updated_by` / `updated_at` | 最近修改人和修改时间 | UTC，不保存密码正文 |

### 12.3 Token Redis 契约

原始 Token 格式为公开 `userId` 与至少 256 位随机秘密的组合。请求使用 `Authorization: Bearer <token>`，不得通过 URL、Cookie 或查询参数传递。

| Redis 数据 | 含义 | 约束 |
|---|---|---|
| `support-agent:auth:token:{userId}:<sha256>` | 单个登录会话 | 保存用户 ID、用户名、角色、签发和过期时间；TTL 2 小时；不保存原始 Token |
| `support-agent:auth:user-tokens:{userId}` | 用户当前 Token 哈希索引 | 用于注销全部会话；TTL 不短于最长 Token TTL |
| `support-agent:auth:login-limit:<subjectHash>` | 登录失败限流 | 只保存用户名与客户端来源的不可逆哈希及计数，不记录密码 |

Token 创建、单 Token 注销和用户全部 Token 撤销必须使用原子 Redis 操作。认证成功后得到不可变 `AuthenticatedUser(userId, username, role)`，应用用例不得直接解析 HTTP Header。

### 12.4 接口与权限

| 接口 | 含义 | 权限与响应重点 |
|---|---|---|
| `POST /api/v1/auth/login` | 用户名密码登录 | 匿名可用；返回 `accessToken`、`tokenType=Bearer`、`expiresAt` 和用户摘要 |
| `POST /api/v1/auth/logout` | 注销当前 Token | 已登录用户；幂等删除当前 Token |
| `GET /api/v1/users/me` | 查询当前用户 | 已登录用户；不得返回密码哈希或 Token 哈希 |
| `POST /api/v1/admin/users` | 创建用户 | `ADMIN`；支持幂等键；不得在响应中回显初始密码 |
| `PATCH /api/v1/admin/users/{userId}/status` | 启用或禁用账号 | `ADMIN`；禁用立即撤销全部 Token；禁止管理员禁用自己 |

登录失败统一返回稳定错误，不区分“用户不存在”和“密码错误”。同一用户名或来源连续失败必须限流。初始管理员仅在 `app_user` 为空时读取环境变量创建一次，缺失时生产环境启动失败，开发环境必须显式选择是否启用引导。

认证 DTO 字段必须遵循下表，不得让接口层直接暴露数据库实体：

| DTO 字段 | 含义 | 约束 |
|---|---|---|
| `username` | 登录名或管理员要创建的登录名 | 登录时先按用户名规则规范化；日志中只允许脱敏值 |
| `password` | 本次提交的明文密码 | 12～72 个字符且 UTF-8 编码不超过 72 字节，避免 BCrypt 静默截断；只在当前请求内存中短暂存在，不回显、不记录 |
| `displayName` | 用户展示名称 | 创建用户时必填，1～100 字符 |
| `role` | 新用户角色或当前用户角色 | 仅 `USER`、`ADMIN`；登录请求不得自行指定 |
| `status` | 账号当前状态或管理员要设置的状态 | 仅 `ACTIVE`、`DISABLED` |
| `accessToken` | 本次登录签发的原始不透明凭证 | 仅登录成功响应返回一次，不写数据库和日志 |
| `tokenType` | HTTP 认证方案 | 固定为 `Bearer` |
| `expiresAt` | Token 绝对失效时间 | UTC ISO-8601；不代表滑动续期时间 |
| `userId` | 用户公开 UUID | 用于资源归属和审计，不使用数据库自增主键 |

初始管理员配置必须使用环境变量占位，不得把真实值写入 `application.yml`：

| 环境变量 | 含义 | 约束 |
|---|---|---|
| `SUPPORT_AGENT_BOOTSTRAP_ADMIN_ENABLED` | 是否允许执行首次管理员引导 | 默认 `false`；仅用户表为空时生效 |
| `SUPPORT_AGENT_BOOTSTRAP_ADMIN_USERNAME` | 初始管理员登录名 | 启用引导时必填，遵守普通用户名规则 |
| `SUPPORT_AGENT_BOOTSTRAP_ADMIN_DISPLAY_NAME` | 初始管理员展示名称 | 启用引导时必填 |
| `SUPPORT_AGENT_BOOTSTRAP_ADMIN_PASSWORD` | 初始管理员明文密码 | 启用引导时必填，只用于生成 BCrypt 哈希，禁止日志输出 |

认证失败返回 HTTP 401，权限不足返回 403，版本或唯一性冲突返回 409，登录限流返回 429；响应正文继续使用统一 `ApiResult<T>`。

### 12.5 资源归属与迁移

- Redis 会话 Hash 新增 `ownerUserId` 和 `createdAt`。创建会话时写入所有者；读取、续租、提交、摘要、建议消费和后续删除均校验同一用户。
- `ticket` 新增可索引的 `owner_user_id BINARY(16)`。新工单必须有所有者；`USER` 只能访问自己的工单，`ADMIN` 可访问全部工单。
- 既有无所有者工单保留为空，只允许 `ADMIN` 查看和处理，不猜测归属；后续可由管理员显式认领。
- 既有无 `ownerUserId` 的 Redis 会话视为旧版本不可访问数据，保持原 TTL，最长 7 天自然过期，不自动归属给首个访问者。
- `agent_run` 增加 `user_id`，用于安全审计关联；审计日志仍不得记录完整问题、回答或 Token。
- 当前固定 `operatorId` 被认证用户替代；系统异步任务继续使用稳定系统身份。
- 知识文档、已解决案例及用户管理写接口只允许 `ADMIN`；聊天接口允许 `USER` 和 `ADMIN`。

### 12.6 阶段 11 门禁

- 覆盖登录成功、错误密码、用户不存在、禁用账号、限流、注销和 Token 过期。
- 覆盖普通用户跨用户访问会话和工单被拒绝、管理员授权成功、旧无归属数据不可被普通用户接管。
- 验证数据库和 Redis 均不保存明文密码或原始 Token；敏感信息扫描通过。
- 执行 `mvn test`、`mvn verify -Pintegration` 和完整 Review 后停止，不提前实现会话管理。

## 13. 阶段 12：会话生命周期管理

### 13.1 用户能力

| 能力 | 含义 | 关键约束 |
|---|---|---|
| 会话列表 | 按最近访问时间倒序查询当前用户会话 | 使用每用户 Redis 有序索引，不允许使用 `KEYS` 扫描 |
| 会话详情 | 查看摘要元数据、最近完整轮次和版本 | 仅所有者或管理员；响应不得包含 Agent 内部状态 |
| 会话重置 | 保留会话 ID 和所有者，清空上下文后开始新代次 | 必须在无活动运行时原子执行；返回新的 `generation` 和版本 0 |
| 会话删除 | 删除会话、轮次、摘要、幂等消息、建议和索引 | 必须原子校验所有者与运行状态；删除后不可继续使用旧版本 |

会话 Hash 增加 `generation` 表示同一会话 ID 的重置代次。消息幂等键和建议键必须包含代次，避免重置后错误重放旧结果。重置与删除不得删除 MySQL 安全审计记录；审计只保留必要标识和结果分类。

### 13.2 接口

| 接口 | 含义 | 关键字段 |
|---|---|---|
| `GET /api/v1/conversations` | 查询自己的会话列表 | `conversationId`、`status`、`version`、`generation`、`summaryVersion`、`lastAccessAt`、`expiresAt` |
| `GET /api/v1/conversations/{id}` | 查询单个会话详情 | 上述元数据及最近成功轮次；不返回隐藏状态 |
| `POST /api/v1/conversations/{id}/reset` | 原子重置会话 | 请求携带预期版本；响应返回同一 ID、新代次和版本 0 |
| `DELETE /api/v1/conversations/{id}` | 删除会话 | 请求携带预期版本；成功后后续访问返回不存在 |

会话响应字段含义固定如下：`conversationId` 是公开会话 UUID；`status` 是当前是否存在活动运行的状态；`version` 是成功提交轮次的乐观锁版本；`generation` 是同一会话 ID 的重置代次；`summaryVersion` 是滚动摘要修订版本；`lastAccessAt` 是最后一次成功访问时间；`expiresAt` 是按 Redis TTL 计算的预计过期时间。所有时间均使用 UTC ISO-8601。

阶段 12 必须验证删除完整性、重置隔离、活动运行冲突、并发删除、过期索引清理和越权访问；完成后停止，不实现长期记忆。

## 14. 阶段 13：受用户控制的跨会话长期记忆

### 14.1 安全模型

- 长期记忆默认关闭，由用户显式启用。
- 模型只能产生 `PROPOSED` 候选，不能直接写入有效记忆；用户确认后才变为 `ACTIVE`。
- 第一版只使用 MySQL 结构化记忆，不引入向量库或 Elasticsearch 记忆索引。
- 用户可以查看、更正、撤销和永久删除自己的每条记忆；管理员默认不能读取普通用户记忆正文。
- 密码、Token、密钥、个人敏感数据、隐藏推理、完整 Prompt、知识正文和完整回答禁止进入长期记忆。

### 14.2 `user_memory` 字段

| 字段 | 含义 | 约束 |
|---|---|---|
| `id` / `memory_id` | 内部主键和公开 UUID | 公开接口只使用 `memory_id` |
| `user_id` | 记忆所有者 | 必填，只能由所有者操作 |
| `memory_type` | 记忆类别 | 首版仅 `PREFERENCE`、`CONSTRAINT`、`ENVIRONMENT` |
| `content` | 用户确认后的简短记忆正文 | 有长度上限，必须通过敏感信息扫描 |
| `content_hash` | 规范化正文 SHA-256 | 用于同用户同类型去重，不反推出正文 |
| `status` | 生命周期状态 | `PROPOSED`、`ACTIVE`、`REVOKED` |
| `source_conversation_id` / `source_turn_id` | 候选来源 | 仅做可追溯标识，不复制完整会话 |
| `expires_at` | 可选过期时间 | 到期后不再注入上下文 |
| `version` | 乐观锁版本 | 更正、确认、撤销时校验 |
| 审计时间与操作者字段 | 创建、确认、更新和撤销记录 | 使用 UTC，不记录模型正文之外的数据 |
| `pinned` | 用户是否显式固定该条记忆 | 默认 `false`；固定记忆在独立 Token 预算内优先注入 |

### 14.3 注入与接口边界

- 上下文优先级调整为：系统规则、当前问题、当前证据、已确认长期记忆、单会话摘要、最近完整轮次。
- 长期记忆必须受独立 Token 上限约束，按类型优先级、更新时间和显式固定标志选择；不得挤占当前问题或证据。
- 提供记忆开关、列表、候选确认、正文更正、撤销和永久删除接口；所有写操作使用乐观锁和幂等键。
- 评测必须覆盖错误归属、敏感候选、冲突记忆、过期记忆、用户撤销和删除后不再注入。

公共接口固定为：`GET/PATCH /api/v1/users/me/memory-settings` 管理本人开关；`GET /api/v1/memories` 查询本人记忆；`POST /api/v1/memories/{memoryId}/confirm` 确认候选；`PATCH /api/v1/memories/{memoryId}` 更正正文或过期时间；`POST /api/v1/memories/{memoryId}/revoke` 撤销注入资格；`DELETE /api/v1/memories/{memoryId}` 永久删除。模型候选创建是内部应用能力，不向客户端提供可伪造来源的创建接口。

记忆接口中的 `enabled` 表示用户是否允许生成和注入长期记忆；`memoryId` 是公开记忆 UUID；`memoryType` 是记忆类别；`content` 是用户可见且确认后的正文；`status` 是候选、有效或已撤销状态；`sourceConversationId` 和 `sourceTurnId` 只用于说明来源；`expiresAt` 是可选失效时间；`version` 用于并发写校验。字段为空时的语义必须由 DTO 校验明确，不得用空字符串同时表示“未设置”和“删除”。

阶段 13 完成后停止，不自动接入相似度召回或用户画像推断。

### 14.4 阶段 13 补充冻结参数

- 每次成功提交聊天轮次后，仅在用户已经启用长期记忆时异步生成候选；候选失败不影响已完成的聊天，不执行自动重试。
- 候选模型固定使用 `qwen3.7-flash`，通过独立 `UserMemoryCandidatePort` 调用，不复用 Chat 或摘要端口。
- 单条记忆正文最多 500 个 Unicode 字符；每位用户最多保留 100 条未永久删除的记忆。
- 单次模型上下文最多注入估算 1,000 Token 的有效长期记忆，选择优先级固定为：`pinned`、`CONSTRAINT`、`ENVIRONMENT`、`PREFERENCE`、最近更新时间。
- 使用独立 `user_memory_settings` 保存用户开关和乐观锁版本。设置修改、候选确认、更正、撤销与永久删除均校验预期版本；所有公共写接口使用 `Idempotency-Key` 请求头。
- 候选来源 `sourceConversationId` 使用公开会话 UUID，`sourceTurnId` 使用成功轮次对应的 `clientMessageId`；不得复制完整会话正文。

## 15. 阶段 14：账号安全与认证演进

阶段 14 在不改变本地账号主路径的前提下补齐：

- 用户修改自己的密码，必须校验旧密码并撤销其他 Token。
- 管理员重置密码，首次登录必须修改；新密码仍不得通过日志或响应回显。
- 登录失败递增退避、临时锁定、管理员解锁、全量 Token 撤销和安全事件审计。
- 用户列表和角色、状态管理；角色仍只允许 `USER`、`ADMIN`，不在本阶段扩展复杂 RBAC。
- 定义 `AuthenticationPort`、外部主体映射和账号关联边界，为未来 OIDC/SSO 预留替换点，但不接入真实外部身份提供商。
- 评估 Token TTL、并发登录数量和账号安全事件指标；任何调整必须先更新冻结参数。

阶段 14 至少提供用户改密、管理员重置密码、管理员解锁、撤销本人全部 Token 和管理员撤销指定用户全部 Token 的接口。改密请求中的 `oldPassword` 是当前密码，`newPassword` 是待设置密码；管理员重置请求中的 `newPassword` 是一次性初始密码；`mustChangePassword` 表示用户下次认证后是否必须先改密；`lockedUntil` 表示临时锁定截止时间，空值表示未被临时锁定。

阶段 14 不实现组织架构、多租户、第三方登录页面、OAuth 授权服务器或企业 SSO 联调。

## 16. 阶段 11～14 通用安全与测试门禁

- 所有普通 JSON 接口继续使用 `ApiResult<T>`；认证失败使用正确 HTTP 状态，不把所有错误包装为 200。
- Controller 只读取认证上下文并调用应用用例；资源所有权必须在应用层再次校验，不能只依赖 URL 或 Controller。
- 密码、原始 Token、Token 哈希和敏感记忆不得进入 Git、日志、异常、测试报告或模型上下文。
- MySQL 迁移只追加；不得修改既有迁移或使用数据库级联删除。
- 每阶段必须包含单元测试、MySQL/Redis 集成测试、架构测试、越权测试、敏感信息扫描、完整 Review 和独立工作记录。
- 用户决定暂缓的真实模型评测必须明确记为未验证，不得据此宣称对应在线质量门禁通过。
