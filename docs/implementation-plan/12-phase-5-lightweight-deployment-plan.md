# Support Agent 五期轻量级学习部署实施计划

> 状态：已冻结，等待用户明确下达“执行阶段 18”指令。
>
> 版本：1.0；冻结日期：2026-09-22；本计划只用于获得第一次完整云服务器部署经验，不代表生产高可用方案。

## 1. 目标

在不实现前端、不引入高可用和自动化发布平台的前提下，把当前 Support Agent 后端完整部署到一台云服务器，并从开发电脑通过 Apifox、Postman 或 IDEA HTTP Client 验证真实业务链路。

本阶段完成后，操作者应能够理解并实际完成以下流程：

1. 本地构建可执行 JAR，并确认测试和制品摘要。
2. 在云服务器上使用 Docker Compose 启动 MySQL、Redis 和 Elasticsearch。
3. 使用受管理的系统服务运行 Spring Boot JAR，并通过环境变量注入配置和秘密。
4. 通过 SSH 隧道访问后端，不直接向公网开放业务端口或基础设施端口。
5. 完成登录、知识发布、异步任务和 SSE 聊天的最小端到端验证。
6. 重启应用和服务器后确认数据、容器与应用能够恢复。

## 2. 冻结决策

| 编号 | 决策 | 冻结结论 |

## 3. 冻结拓扑

```text
开发电脑
  ├─ Apifox / Postman / IDEA HTTP Client
  └─ localhost:18080
            │
            │ SSH 本地端口转发
            ▼
云服务器 127.0.0.1:8080
  └─ Support Agent 可执行 JAR（prod）
       ├─ 127.0.0.1:3306 -> MySQL 容器
       ├─ 127.0.0.1:6379 -> Redis 容器
       ├─ 127.0.0.1:9200 -> Elasticsearch + ICU 容器
       └─ HTTPS -> DashScope
```

云防火墙或安全组只允许操作者来源 IP 访问 SSH。`8080`、`3306`、`6379` 和 `9200` 均不得向公网开放。现有基础设施端口已经绑定回环地址，阶段 18 必须保留该边界。

开发电脑建立隧道的命令形式为：

```powershell
ssh -L 18080:127.0.0.1:8080 <server-user>@<server-ip>
```

隧道建立后，本地客户端使用 `http://127.0.0.1:18080`。此方式仅用于个人学习验证，不替代后续正式环境中的 HTTPS 和反向代理。

## 4. 阶段 18：轻量级云服务器部署

### 4.1 实施范围

#### A. 部署材料

- 增加独立的轻量部署目录，不修改或冒充现有本地 `deploy/compose.yml` 的语义。
- 提供服务器基础设施 Compose 文件或受控覆盖文件，继续使用已冻结的 MySQL、Redis、Elasticsearch 和 ICU 版本。
- 为三个容器增加适合学习服务器的重启策略、健康检查和命名数据卷。
- 提供不含真实秘密的应用环境变量模板。
- 提供系统服务定义，使应用使用 Java 21、`prod` Profile 和服务器本地环境文件启动。
- 提供完全使用 PowerShell 7 表达的本地构建、上传、隧道和验证说明；不得只提供 Bash 可用的命令。

#### B. 本地构建与制品

- 开始部署前执行 `mvn test`。
- 使用 `mvn -pl support-agent-bootstrap -am package` 构建可执行 JAR。
- 记录 Git 提交、JAR 文件名、大小和 SHA-256，不在服务器上从未知工作区临时编译。
- 上传 JAR、部署文件和必要配置模板，不上传 `.env`、测试报告、IDE 配置或源码中的本地临时文件。

#### C. 服务器准备

- 安装 Java 21、Docker Engine、Docker Compose 和 PowerShell 7；实际安装步骤应引用所选云厂商或发行版的官方说明。
- 创建专用低权限运行用户和固定部署目录，不使用个人主目录散放制品。
- 配置时间同步、至少 2 GiB Swap 或等效内存保护，并检查磁盘可用空间。
- 安全组仅保留受限 SSH；确认所有业务与数据端口未暴露公网。

#### D. 配置与首次启动

- 为 MySQL 业务用户和 root 用户生成不同的随机强密码。
- 配置 `DASHSCOPE_API_KEY`、数据库连接、Redis 和 Elasticsearch 地址。
- 显式设置 `SPRING_PROFILES_ACTIVE=prod` 与应用监听地址 `127.0.0.1`。
- 首次空库启动时临时启用管理员引导并设置初始管理员；确认创建成功后，关闭引导、删除环境文件中的初始明文密码并重新启动。
- 先等待三个基础设施健康，再启动应用系统服务；Flyway 迁移失败时不得绕过或手工伪造版本记录。

#### E. 端到端验证

- 通过 SSH 隧道检查 liveness、readiness 和 info。
- 验证未认证请求被拒绝、管理员可以登录且强密码有效。
- 导入一份不含敏感信息的测试知识，发布后确认异步任务成功并能被检索。
- 使用唯一 `clientMessageId` 调用 SSE Chat，确认收到合法终止事件；有可靠知识时确认回答包含引用。
- 验证普通用户只能访问自己的会话和工单，管理员接口仍受角色保护。
- 重启应用，确认系统服务自动恢复且 MySQL 数据、Redis Token 和 Elasticsearch 索引仍存在。
- 在维护窗口重启云服务器，确认容器和应用能按设计恢复；若不能自动恢复，阶段不得标记完成。

### 4.2 交付物

- 轻量部署 Compose 或 Compose 覆盖文件。
- 应用环境变量示例，不含任何真实秘密。
- 应用系统服务定义。
- 从购买服务器后的准备、上传、启动、隧道、验证、重启到停止的中文部署手册。
- 一份阶段 18 工作记录，包含服务器规格、开放端口、制品 SHA-256、实际命令、验证结果和未完成项；不得记录公网密码、Token 或 DashScope Key。

### 4.3 验收门禁

以下条件全部满足后，阶段 18 才能标记为已完成：

- [ ] `mvn test` 通过，实际数量和结果已记录。
- [ ] `mvn verify -Pintegration` 通过；若本地 Docker 不可用，必须在具备 Docker 的受控环境补跑，不能仅引用历史结果完成阶段。
- [ ] 可执行 JAR 构建成功并记录 SHA-256。
- [ ] 云安全组未开放 `8080`、`3306`、`6379` 和 `9200`。
- [ ] 三个基础设施容器健康，应用系统服务处于运行状态。
- [ ] 应用确实以 `prod` Profile 启动，Swagger 在生产 Profile 下不可用。
- [ ] liveness、readiness 和 info 通过 SSH 隧道可访问。
- [ ] 登录、知识发布、异步任务完成和 SSE Chat 最小链路通过。
- [ ] 初始管理员引导已关闭，环境文件中不再保留初始明文密码。

## 5. 明确不在范围

阶段 18 不实现以下内容：

- 前端页面、移动端或桌面客户端。
- 域名、Nginx、HTTPS 证书和公网业务访问。
- 应用 Docker 镜像、镜像仓库、CI/CD 或自动回滚。
- Kubernetes、负载均衡、多应用实例、数据库主从或跨区域灾备。
- 云托管 MySQL、Redis 或 Elasticsearch。
- Prometheus、Grafana、集中日志平台和自动告警。
- SSO、OIDC、MFA、多租户或复杂 RBAC。
- 正式备份策略、RPO/RTO 承诺或生产 SLA。
- 全量 Elasticsearch 运维重建工具。
- 未经单独授权的完整真实模型在线测试。

这些排除项只约束本次学习部署，不表示后续不需要。阶段 18 完成后，如用户希望继续学习，可另行冻结“应用容器化与 HTTPS”“自动发布”“监控与备份”等独立阶段。

## 6. 风险与接受边界

- 单机故障会导致整个系统不可用；本阶段接受该风险。
- Elasticsearch 关闭自身安全认证，但只允许通过服务器回环地址访问；若端口暴露公网，必须立即停止而不是继续部署。
- SSH 隧道关闭后，本地客户端无法访问应用，这是预期行为。
- Redis 丢失会导致 Token、会话和建议失效；MySQL 与 Elasticsearch 命名卷损坏仍可能造成数据丢失，本阶段不承诺灾难恢复。
- DashScope 是唯一模型供应商，网络或配额异常会影响模型相关功能。
- 本阶段使用 `prod` Profile 是为了验证真实配置边界，不代表该单机环境已经达到生产级别。
