# Support Agent 四期知识空间实施计划

> 版本：1.0；编制日期：2026-09-27；状态：用户已确认，阶段 18 已完成并通过门禁，阶段 19～20 待执行。
>
> 本文把 [四期知识空间冻结方案](../design-freezes/04-phase-4-knowledge-space.md) 拆分为三个可独立验收阶段。本文不是当前执行授权；只有用户明确确认本计划并下达“执行阶段 N”指令后，才能开始对应阶段。

## 1. 目标与依据

四期在单企业私有化部署边界内新增知识空间，使个人资源、业务域知识和企业公共知识具有明确归属。最终形成以下运行语义：

```text
认证用户
  ├─ 个人会话、个人长期记忆、本人工单
  ├─ GLOBAL 企业公共知识
  └─ 当前活动知识空间的业务域知识

一次 Chat 检索范围 = GLOBAL + 当前会话活动空间
```

实施必须同时遵守：

1. [四期知识空间冻结方案](../design-freezes/04-phase-4-knowledge-space.md)。
2. [当前系统基线](10-current-system-baseline.md)。
3. `docs/standards/` 全部强制规范。
4. 当前阶段开始时最新的一份 `docs/work-logs/` 记录。
5. 阶段涉及的既有领域、API、RAG、安全和前端计划。

冻结方案与本文冲突时，以冻结方案为准并暂停实施；不得在阶段内自行改变业务语义。

## 2. 阶段总览

| 阶段 | 名称 | 核心结果 | 前置条件 |
|---:|---|---|---|
| 18 | 知识空间基础与历史数据归属 | 建立空间、成员和 MySQL 资源归属，历史数据无损迁入 `GLOBAL`，检索行为保持不变 | 阶段 17 完成；本计划获得确认 |
| 19 | 范围化索引、检索与会话绑定 | 新索引携带 `spaceId`，BM25、向量和 MySQL 回查双重过滤；会话、工单、案例形成完整空间链路 | 阶段 18 门禁全部通过 |

## 3. 四期统一冻结契约

### 3.1 标识与系统空间

- `spaceId` 使用公开 UUID；MySQL 保存为 `BINARY(16)`，API 和 Redis 使用标准 UUID 字符串，Elasticsearch 使用 `keyword`。
- 系统 `GLOBAL` 空间的固定 UUID 为 `00000000-0000-0000-0000-000000000001`，代码固定为 `GLOBAL`。
- `GLOBAL` 的 `visibility=ENTERPRISE`、`status=ACTIVE`、`systemSpace=true`；不得删除、停用、修改代码或改为受限空间。
- 所有有效用户隐式拥有 `GLOBAL` 读取权限，不创建逐用户 `READER` 成员记录。
- 历史托管文档、工单和案例全部回填 `GLOBAL`，不得根据正文、创建者或工单内容推断其他空间。

### 3.2 `knowledge_space` 精确字段

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| `id` | `BIGINT` 自增主键 | MySQL 内部主键，不通过 API 暴露 |
| `space_id` | `BINARY(16)`，唯一、非空 | 公开空间 UUID |
| `code` | `VARCHAR(64)`，ASCII 二进制排序、唯一、非空 | 稳定空间代码；格式 `[A-Z][A-Z0-9_-]{1,63}`，创建后不可修改 |
| `name` | `VARCHAR(100)`，非空 | 空间名称，去除首尾空白后 1～100 字符 |
| `description` | `VARCHAR(500)`，可空 | 空间用途和边界说明 |
| `visibility` | `VARCHAR(16)`，非空 | `ENTERPRISE` 或 `RESTRICTED` |
| `status` | `VARCHAR(16)`，非空 | `ACTIVE` 或 `DISABLED` |
| `system_space` | `BOOLEAN`，非空 | 是否为系统空间；四期只有 `GLOBAL=true` |
| `version` | `BIGINT`，非空、初始 0 | 乐观锁版本 |
| 审计字段 | 创建/更新主体与 UTC 时间 | 不保存密码、Token 或请求正文 |

空间不提供物理删除。`DISABLED` 空间禁止新建会话、新建或修改知识、发布、归档和创建工单；已存在资源保留审计事实。授权用户和平台管理员仍可查看空间元数据，普通 Chat 不得继续使用其知识。

### 3.3 `user_space_membership` 精确字段

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| `id` | `BIGINT` 自增主键 | MySQL 内部主键 |
| `user_id` | `BINARY(16)`，非空 | 成员公开用户 UUID |
| `space_id` | `BINARY(16)`，非空 | 所属空间 UUID |
| `role` | `VARCHAR(16)`，非空 | `READER`、`EDITOR` 或 `MANAGER` |
| `status` | `VARCHAR(16)`，非空 | `ACTIVE` 或 `REVOKED` |
| `version` | `BIGINT`，非空、初始 0 | 角色变化和撤销的乐观锁版本 |
| 审计字段 | 创建、更新、撤销主体与 UTC 时间 | 支持成员变更追踪 |

- `(user_id, space_id)` 唯一；重新加入使用原记录从 `REVOKED` 恢复为 `ACTIVE`，不得插入重复行。
- 成员角色权限包含关系固定为 `MANAGER > EDITOR > READER`。
- `GLOBAL` 不允许创建 `READER` 成员；只有需要编辑或管理 `GLOBAL` 时才保存 `EDITOR` 或 `MANAGER` 记录。
- 被禁用用户的成员记录保留，但任何空间权限判断都必须先要求用户账号为 `ACTIVE`。
- 不使用数据库级联删除。

### 3.4 既有资源字段与唯一约束

以下字段最终均为非空 `BINARY(16)`：

- `managed_document.space_id`
- `ticket.space_id`
- `resolved_case.space_id`

三张业务表的 `space_id` 以及 `user_space_membership.space_id` 必须引用 `knowledge_space.space_id`；成员 `user_id` 必须引用 `app_user.user_id`。所有外键均禁止级联删除或级联更新。

`managed_document` 当前的全局活动内容哈希唯一约束调整为 `(space_id, active_content_hash)`：同一空间内禁止重复活动内容，不同空间允许相同正文。重复错误不得透露其他空间是否已有相同内容。

案例空间必须与来源工单一致。创建案例时复制工单 `spaceId`，更新和发布前再次校验；不得提供直接修改案例空间的接口。

### 3.5 空间访问判定

应用层建立统一的空间访问服务或端口，所有用例复用同一判定：

- 平台 `ADMIN`：可以治理全部空间和资源，但不能绕过 `GLOBAL` 不变量、安全网关和审计。
- `ENTERPRISE + ACTIVE`：所有 `ACTIVE` 用户拥有读取权限；编辑和管理仍要求有效成员角色。
- `RESTRICTED + ACTIVE`：读取要求至少 `READER`，编辑要求至少 `EDITOR`，成员治理、发布和归档要求 `MANAGER`。
- `DISABLED`：不参与新检索和写操作；只有平台管理员以及该空间既有有效成员可读取空间元数据和历史资源审计信息。
- 对完全无权访问的受限空间统一返回 `KNOWLEDGE_SPACE_NOT_FOUND`，避免泄露空间是否存在。

权限判断必须在应用层执行。Controller、前端、MyBatis 查询条件或 Elasticsearch 过滤都不能单独成为授权边界。

### 3.6 公共错误码

| 错误码 | HTTP | 语义 |
|---|---:|---|
| `KNOWLEDGE_SPACE_NOT_FOUND` | 404 | 空间不存在或当前用户完全无权获知该空间 |
| `KNOWLEDGE_SPACE_ROLE_REQUIRED` | 403 | 用户可以看到空间，但缺少当前操作要求的 `EDITOR` 或 `MANAGER` 角色 |
| `KNOWLEDGE_SPACE_DISABLED` | 409 | 已知空间处于停用状态，禁止当前操作 |
| `KNOWLEDGE_SPACE_CODE_CONFLICT` | 409 | 空间代码已存在 |
| `KNOWLEDGE_SPACE_VERSION_CONFLICT` | 409 | 空间或成员乐观锁版本冲突 |
| `KNOWLEDGE_SPACE_GLOBAL_IMMUTABLE` | 409 | 尝试修改 `GLOBAL` 的系统不变量 |
| `KNOWLEDGE_SPACE_MEMBERSHIP_CONFLICT` | 409 | 成员状态或角色操作与当前状态冲突 |
| `CHAT_SPACE_MISMATCH` | 409 | 请求空间与既有会话当前代际绑定空间不一致 |
| `KNOWLEDGE_SPACE_CONTEXT_REQUIRED` | 400 | 最终契约要求空间但请求未提供，且不适用历史兼容规则 |

错误响应继续使用 `ApiResult`；已经建立的 SSE 内错误继续遵守现有 SSE 协议。错误消息不得包含无权空间名称、文档标题、命中数量或成员信息。

### 3.7 公共 API 方向

空间 API 固定如下，精确 DTO 字段在阶段 18 写入 OpenAPI：

| 接口 | 最低权限 | 用途 |
|---|---|---|
| `GET /api/v1/knowledge-spaces` | 已认证 | 列出当前用户可读的 `ACTIVE` 空间；管理员可用状态筛选查看全部 |
| `GET /api/v1/knowledge-spaces/{spaceId}` | `READER` 或隐式企业读取 | 查看空间详情；无权时返回 404 |
| `POST /api/v1/admin/knowledge-spaces` | 平台 `ADMIN` | 创建空间 |
| `PATCH /api/v1/admin/knowledge-spaces/{spaceId}` | 平台 `ADMIN` | 修改名称、说明、可见性，使用乐观锁 |
| `POST /api/v1/admin/knowledge-spaces/{spaceId}/disable` | 平台 `ADMIN` | 停用空间，禁止 `GLOBAL` |
| `POST /api/v1/admin/knowledge-spaces/{spaceId}/enable` | 平台 `ADMIN` | 恢复已停用空间，使用乐观锁并记录审计 |
| `GET /api/v1/knowledge-spaces/{spaceId}/members` | `MANAGER` 或平台 `ADMIN` | 分页查询成员 |
| `PUT /api/v1/knowledge-spaces/{spaceId}/members/{userId}` | `MANAGER` 或平台 `ADMIN` | 新增、恢复或修改成员角色 |
| `DELETE /api/v1/knowledge-spaces/{spaceId}/members/{userId}` | `MANAGER` 或平台 `ADMIN` | 撤销成员关系，不物理删除记录 |

所有写接口要求 `Idempotency-Key`；请求正文中的 `expectedVersion` 用于乐观锁。成员管理者不得通过撤销或降级最后一个有效 `MANAGER` 让受限空间失去业务管理员；平台管理员不计入该数量但可以执行紧急恢复。

### 3.8 客户端兼容策略

- 阶段 18 期间，既有未携带 `spaceId` 的资源创建请求仅能落入 `GLOBAL`，用于保持现有前端 F1～F3 和 HTTP 示例可用；响应立即返回实际 `spaceId`。
- 阶段 19 新增显式空间字段并发出兼容告警，但服务端仍只对缺失字段默认 `GLOBAL`，绝不根据用户其他成员关系猜测空间。
- 阶段 20 验收前必须根据前端计划单独完成客户端空间选择适配；之后将新建会话、手工工单和知识草稿的 `spaceId` 改为必填。已有会话继续使用持久化空间，不受请求字段缺省影响。
- 前端修改必须遵守 `docs/frontend/implementation-plan/`，不得夹带在后端阶段中以静态页面或 Mock 代替真实接口。若前端适配尚未完成，阶段 20 不得通过最终兼容门禁。

## 4. 阶段 18：知识空间基础与历史数据归属

### 4.1 目标

建立空间和成员治理的领域、存储与 API 基础，并为既有 MySQL 资源补齐 `GLOBAL` 归属。阶段结束时检索和 Chat 行为保持当前全局知识语义，不提前启用受限空间检索。

### 4.2 必须交付

#### A. 领域与应用边界

- 新增 `KnowledgeSpace`、`KnowledgeSpaceVisibility`、`KnowledgeSpaceStatus`、`SpaceMembership`、`SpaceRole` 等领域对象及完整状态规则。
- 新增统一空间访问判定服务，覆盖平台角色、空间可见性、成员状态、成员角色和账号状态。
- 新增空间查询、创建、修改、停用和成员增改撤用例；不得让 Controller 直接调用 Mapper。
- 空间和成员的所有手写类、构造器及方法提供有效 Javadoc。

#### B. Flyway V9 与历史迁移

- 新建 `knowledge_space` 和 `user_space_membership`，包含本计划第 3 节冻结字段、索引、检查约束和中文注释。
- 在同一追加迁移中插入固定 `GLOBAL` 空间，重复启动必须由 Flyway 版本机制保证不会重复创建。
- 为 `managed_document`、`ticket`、`resolved_case` 增加临时可空 `space_id`，全部回填 `GLOBAL` 后校验空值数量为 0，再改为非空并增加索引。
- `resolved_case.space_id` 必须按来源工单回填；若发现来源工单空间为空或不一致，迁移必须失败，不得静默修复为猜测值。
- 把文档活动内容唯一约束改为 `(space_id, active_content_hash)`，保留同空间并发唯一性。
- 更新集成测试中的表、字段、索引、约束和注释数量，不以放宽断言绕过迁移验证。

#### C. 空间治理 API

- 实现第 3.7 节全部空间和成员 API、OpenAPI 中文字段说明及 `http/` 示例。
- 列表默认只返回当前用户可读的 `ACTIVE` 空间，排序固定为 `GLOBAL` 在前，其余按 `name`、`spaceId` 稳定排序。
- 平台管理员可以按 `status`、`visibility`、关键字分页查询全部空间；普通用户不得使用管理筛选扩大范围。
- 空间创建默认 `visibility=RESTRICTED`、`status=ACTIVE`，创建者为平台管理员时不自动生成业务成员关系。
- `GLOBAL` 修改、停用、代码变化和非法成员操作必须由领域规则与应用层共同拒绝。

#### D. 审计与安全

- 扩展 `security_event` 的稳定事件类型，至少覆盖空间创建、更新、停用、成员新增、角色变化、恢复和撤销。
- V9 为 `security_event` 增加可空 `resource_type`、`resource_id`：空间事件固定 `resource_type=KNOWLEDGE_SPACE`，`resource_id` 保存空间 UUID；成员事件固定 `resource_type=SPACE_MEMBERSHIP`，同时使用既有 `target_user_id` 标识目标用户。增加 `(resource_type, resource_id, occurred_at, id)` 查询索引，不建立级联关系。
- 审计只记录事件类型、目标资源标识、目标用户、操作者、结果、低基数原因和时间；不记录空间名称、说明、用户名或请求正文。审计中的资源 UUID 用于合规追踪，不得复制为 Micrometer 标签。
- 指标标签禁止包含 `spaceId`、空间代码、名称、用户 ID 或正文。
- 所有不可见空间使用 404 防枚举；成员列表不得返回密码、Token、安全锁定细节或其他无关账号字段。

#### E. 既有资源兼容

- 领域对象、DO、Mapper 和响应 DTO 增加 `spaceId` 与最小空间摘要；现有资源全部返回 `GLOBAL`。
- 阶段 18 中既有创建路径缺少 `spaceId` 时只能默认 `GLOBAL`，并在应用层显式完成，数据库不得使用隐藏默认值掩盖调用方缺失。
- 不允许在阶段 18 把新建文档、工单或案例归入非 `GLOBAL` 空间；受限空间资源写入与检索属于阶段 19。

### 4.3 重点测试

- `GLOBAL` 固定 UUID、隐式读取、不可停用、不可改代码和不可删除。
- `ENTERPRISE`、`RESTRICTED` 与三个空间角色的完整权限矩阵。
- 成员新增、恢复、改角色、撤销、版本冲突、最后一个 `MANAGER` 保护和并发幂等。
- V9 从 V8 数据库迁移：历史文档、工单、案例全部归入 `GLOBAL`，数量和关联不丢失。
- 同空间重复内容仍冲突，不同空间的约束结构允许后续保存相同内容。
- 无权用户无法通过详情、列表、成员接口、错误消息或计数发现受限空间。
- 现有 Chat、工单、文档、案例和长期记忆回归测试继续通过，检索结果与阶段 17 基线一致。

### 4.4 门禁与停止点

执行：

```powershell
mvn test
mvn verify -Pintegration
```

完成全量差异 Review、敏感信息扫描、OpenAPI 启动验收、V8→V9 迁移验证和阶段 18 工作记录后停止。不得提前修改 Elasticsearch Mapping、BM25/向量查询、会话空间绑定或开放非 `GLOBAL` 资源写入。

## 5. 阶段 19：范围化索引、检索与会话绑定

### 5.1 目标

让托管文档、工单、案例、会话和 Elasticsearch 分块形成完整空间链路，并把普通问答检索严格限制为 `GLOBAL + 当前活动空间`。

### 5.2 必须交付

#### A. 资源空间归属

- 托管文档创建请求支持显式 `spaceId`；创建和修改草稿要求 `EDITOR`，发布和归档要求 `MANAGER` 或平台管理员。`READER` 只能读取已发布来源的允许公开内容和元数据，不得查看未发布草稿或失败详情。
- 已发布文档禁止直接改空间；跨空间迁移只能归档旧来源并在目标空间重新创建、审核和发布。
- 手工工单创建支持显式 `spaceId`，只要求用户对空间具有读取权限；工单访问仍遵守“本人或平台管理员”，空间成员不能查看他人工单。
- 从会话建议创建的工单忽略客户端伪造空间，强制继承建议所属会话空间。
- 案例生成复制来源工单空间；查看或修改案例草稿要求对应空间 `EDITOR`，发布、拒绝和归档要求 `MANAGER` 或平台管理员，发布前再次校验案例与工单空间一致。`READER` 只能读取已发布案例的允许公开内容和元数据，不能查看来源工单或案例草稿。
- 文档、工单、案例列表增加授权范围过滤和 `spaceId` 条件；完全无权资源统一表现为不存在。
- 调整 Spring Security URL 规则：知识、案例和与其关联的异步任务入口由“仅平台管理员”改为“已认证后进入应用层空间授权”；管理员用户治理等无关接口仍保持原规则。不得只修改 URL 规则而遗漏应用层校验。

#### B. Redis 会话空间

- Redis 会话 Hash 新增 `spaceId`，并纳入创建、读取、续租、提交、摘要、建议、重置、删除和 Lua 原子脚本校验。
- 新会话由认证用户显式选择可读的 `ACTIVE` 空间；请求省略时仅在兼容窗口绑定 `GLOBAL`。
- 既有无 `spaceId` 会话在首次读取时按固定 `GLOBAL` 兼容，并通过原子操作写回；不得分析历史正文推断空间。
- 同一会话代际不能更换空间。重置开始新代际时可以显式选择新空间，并同时清空旧代际摘要、轮次、建议和消息幂等状态。
- 请求提供的空间与既有会话代际不一致时返回 `CHAT_SPACE_MISMATCH`，不得开始模型调用或创建新轮次。

#### C. Elasticsearch 新索引

- 在 `IndexedKnowledgeChunk`、检索证据和 Elasticsearch 严格 Mapping 中增加非空 `spaceId: keyword`。
- 创建新的物理索引版本；不得原地修改当前索引，也不得按空间拆分多个索引。
- 为所有当前 `PUBLISHED` 文档和案例提供受控全量重建路径，复用现有分块、Embedding 和 Bulk 完整性校验。
- 重建前从 MySQL 读取来源真实 `spaceId`；任务载荷或客户端不得覆盖空间。
- 完整性验证至少比较来源数量、来源版本、每来源分块数量、总分块数量和所有分块 `spaceId`；任何缺失或未知空间必须阻止别名切换。
- 别名原子切换成功后才能启用范围化检索；旧索引保留到回滚窗口结束，不自动删除。
- `KNOWLEDGE_INDEX` 和案例发布处理器在执行前重新读取聚合空间与空间状态。空间已停用时不得写入新分块；已产生的当前任务版本分块必须清理，并把任务收敛为既有 `CANCELLED` 状态，稳定原因码为 `KNOWLEDGE_SPACE_DISABLED`，不得进入重试。`KNOWLEDGE_DELETE` 在空间停用后仍允许执行，因为它只收窄可见范围，但同样必须校验聚合空间和版本。
- 已经成功发布的来源在空间停用后可以暂留索引，但 Elasticsearch 允许集合和 MySQL 有效性回查都必须排除该空间；重新启用后仅在来源仍为当前 `PUBLISHED` 版本时恢复可见。

#### D. 双重过滤检索

- 检索应用端口由 `retrieve(query)` 演进为显式接收认证主体、活动空间和允许空间集合的访问上下文；空上下文必须失败。
- 允许集合由服务端固定构造：活动空间为 `GLOBAL` 时只有 `GLOBAL`；否则为 `GLOBAL + activeSpaceId`。
- BM25 `bool.filter` 与向量 `knn.filter` 使用完全相同的 `spaceId` 集合，测试必须验证两条查询 DSL。
- MySQL 来源有效性回查同时校验来源状态、版本和来源 `spaceId` 属于本次允许集合。
- RRF、Rerank、可靠门槛和同来源最多两个分块规则保持不变，不因空间过滤自动降低阈值。
- 搜索适配器遇到索引命中缺少 `spaceId`、未知空间或不在允许集合时必须剔除并记录低基数诊断；访问上下文整体缺失时必须返回故障，不能退化成全局搜索。

#### E. Chat、引用与工单建议

- Chat 在意图识别前确认会话空间仍为 `ACTIVE` 且用户仍有读取权限；失败时不调用模型、不写入轮次。
- `SUPPORT_QUERY` 使用范围化检索；问候和工单查询仍携带空间上下文，但不得扩大工单工具权限。
- 引用元数据增加 `spaceId`，服务端验证每个引用均属于本次允许集合；客户端不得借引用 ID 获取其他空间来源。
- `ticket.suggested` 冻结会话空间；建议消费和创建草稿时再次校验空间及用户权限。
- LLM 输入安全、输出安全网关、个人长期记忆注入和会话摘要语义保持不变。共享空间知识不得写入 `user_memory`。
- 异步任务详情和列表对空间 `MANAGER` 只展示其空间内的 `KNOWLEDGE_INDEX`、`KNOWLEDGE_DELETE` 任务；平台管理员保留全局访问。人工重试必须重新校验关联资源、空间状态和角色。`CASE_GENERATION` 涉及原始工单事实，四期仍只允许平台管理员查看和重试。

#### F. 评测兼容

- 既有锁定检索数据全部显式标记为 `GLOBAL`，指标口径和期望来源不变。
- 检索评测接口仅允许开发/测试环境，并显式接收测试空间上下文；不得通过评测接口绕过生产权限。
- 新增最小跨空间集成语料，验证相同或相似问题在两个受限空间中不会串扰，但阶段 20 才建立完整固定隔离评测集。

### 5.3 重点测试

- 文档、手工工单、会话工单建议和案例的空间继承、越权、停用和版本冲突。
- 知识与案例 URL 放行后应用层授权仍有效；异步任务列表、详情和人工重试不能跨空间或泄露 `CASE_GENERATION` 工单事实。
- Redis 新会话、历史无字段会话、重置换空间、同代际换空间拒绝、并发运行和 Lua 原子性。
- BM25 和向量两条召回都包含同一空间过滤；单分支降级仍不能跨空间。
- Elasticsearch 全量重建、Bulk 部分失败、空间缺失、完整性失败、别名原子切换和回滚窗口。
- MySQL 来源回查阻止伪造空间、归档来源、过期版本和跨空间候选。
- 同一问题在 `GLOBAL`、空间 A、空间 B 中只返回各自允许证据；Rerank 输入本身不得包含越权候选。
- 引用、SSE、摘要、长期记忆、输入安全和输出网关全量回归。


```powershell

```

未获授权不得宣称真实模型下的范围化问答已经在线验收。阶段 19 完成索引切换、跨空间集成验证、完整 Review、敏感信息扫描和工作记录后停止；不得提前实施阶段 20 的最终治理评测或宣布四期完成。

## 6. 阶段 20：空间权限治理、评测与四期验收

### 6.1 目标

补齐成员撤权、空间停用、角色矩阵、兼容收口、固定安全评测和运行手册，使四期具备可审计、可回归、可恢复的完整交付状态。

### 6.2 必须交付

#### A. 即时权限收敛

- 每次新请求都从 MySQL 读取或通过有明确失效策略的短时缓存取得当前空间权限；不得依赖 Token 签发时的空间角色快照。
- 成员撤销、角色降低、用户禁用或空间停用后，新 Chat、检索、知识写入、建议消费和案例发布立即失败。
- 已经开始的 Chat 不主动向客户端泄露后续证据；权限在模型调用前或答案发送前变化时，至少在发送前重新校验一次，失败则走既有安全错误终止，不发送正文。
- 停用空间不得出现在普通用户可选空间列表，不得继续被 BM25、向量或 MySQL 回查接受。
- 管理员紧急恢复成员和空间状态的行为必须有审计，但本阶段不新增绕过业务状态或直接改库接口。

#### B. 固定隔离评测集

建立不少于 60 条自编、无真实敏感信息的固定 JSONL 数据集：

| 分类 | 最少数量 | 验证目标 |
|---|---:|---|
| `GLOBAL` 与单空间组合 | 15 | 公共知识和当前空间知识可同时召回 |
| 两个受限空间同题或冲突知识 | 15 | 不发生跨空间召回和答案污染 |
| 成员撤销、角色降低、空间停用 | 10 | 权限变化立即生效 |
| 文档、工单、案例继承与引用 | 10 | 全链路空间一致 |
| 防枚举与困难正常样本 | 10 | 不泄露空间存在性，且不误阻断合法访问 |

数据集使用稳定 `caseId`、空间代码、用户角色、输入、期望来源、禁止来源和预期结果，不保存真实企业信息。动态报告写入 `target/knowledge-space-evaluation/`，不得提交 Git。

门槛固定为：

- 跨空间候选进入 Rerank 数量为 0。
- 跨空间引用、回答事实和来源详情泄漏数量为 0。
- 撤权、禁用和停用后的新请求拒绝率为 100%。
- `GLOBAL + 当前空间` 正确来源 Recall@5 不低于四期前锁定基线，且 `noHitAccuracy=1.00`、`exactTermRecall=1.00`。
- 防枚举用例不返回受限空间名称、代码、资源标题、成员或命中数量。

#### C. 可观测性与审计闭环

- 增加低基数指标：空间访问动作、允许/拒绝结果、要求角色、空间可见性类别、活动空间是否为 `GLOBAL`、检索允许空间数量区间、重建结果和拒绝原因。
- 指标和日志禁止包含 `spaceId`、空间代码、名称、用户 ID、会话 ID、文档标题、查询正文或模型输出。
- `retrieval_trace` 候选摘要可以记录来源和分数，但必须确保越权候选在持久化前已被排除；不得新增空间名称或用户成员信息。
- 安全事件覆盖成功和拒绝结果，错误原因保持冻结低基数值。

#### D. 兼容收口与客户端协调

- 清点 `support-agent-web/`、`http/`、OpenAPI 和其他客户端对新建会话、手工工单、文档草稿的调用。
- 前端空间选择与空间治理必须在独立前端阶段按前端实施计划完成并真实联调；本后端阶段不得用 Mock 或固定 `GLOBAL` 页面代替。
- 客户端适配门禁通过后，后端对新建会话、手工工单和知识草稿要求显式 `spaceId`，缺失返回 `KNOWLEDGE_SPACE_CONTEXT_REQUIRED`。
- 历史无空间 Redis 会话兼容读取保留到其原 7 天 TTL 自然结束；不得无限期保留无字段写入路径。
- 更新所有 IDEA HTTP Client 示例，至少覆盖 `GLOBAL`、受限空间、越权、防枚举、撤权和停用。

#### E. 运维与恢复

- 编写知识空间创建、成员治理、空间停用、索引全量重建、别名切换、失败恢复和历史核对手册。
- 提供只读核对命令或受控开发工具，验证 MySQL 已发布来源与 Elasticsearch 来源版本、空间及分块数量一致；不得提供跳过业务状态的生产修改工具。
- 明确回滚边界：数据库迁移不回退；应用可回滚到兼容版本的时间窗口、旧索引保留时间和别名回切条件必须记录。
- 更新当前系统基线、领域字段字典、API/RAG/工程专题文档、根 README 和四期工作记录。

### 6.3 重点测试

- 完整角色矩阵：平台 `USER/ADMIN` × `ENTERPRISE/RESTRICTED` × `READER/EDITOR/MANAGER` × `ACTIVE/DISABLED`。
- 成员撤销、角色降低、用户禁用和空间停用与并发 Chat、知识发布、案例发布的竞态。
- 空间停用与运行中索引任务的竞态：停用后不产生可检索新分块，任务安全收敛，重新启用只恢复当前已发布版本。
- 404 防枚举和 403 已知空间角色不足的稳定区别，且响应不泄露资源信息。
- 60 条固定隔离评测全部达到冻结门槛，重复运行结果一致。
- V8→V9 全迁移、全量重建、别名切换、应用重启和 Redis 历史会话 TTL 路径。
- 既有 239 个及后续新增单元测试、全部基础设施集成测试、架构测试和前端真实联调回归。
- 敏感信息扫描确认无空间成员数据、查询正文、知识正文、Prompt、模型响应和凭据进入日志或报告。

### 6.4 四期完成门禁

必须执行：

```powershell
mvn test
mvn verify -Pintegration
```

前端适配按独立前端阶段执行其冻结的 `npm` 门禁和真实后端联调。真实模型测试仍须单独授权：

```powershell
mvn verify -Ponline-test
```

四期只有在以下条件全部满足后才能标记为已完成：

- 阶段 18～20 规定交付物全部完成。
- MySQL 历史数据、Redis 兼容路径和 Elasticsearch 新索引均通过完整性核对。
- 固定隔离评测达到全部零泄漏和质量门槛。
- 前端或其他正式客户端已经完成显式空间选择适配，不再依赖缺省 `GLOBAL`。
- 完整差异 Review、敏感信息扫描、文档更新和阶段 20 工作记录通过。
- 未获授权的在线模型验证明确记录为未验证，不虚报完成。

通过后停止，不自动提交、推送、执行延期部署或进入下一产品期次。

## 7. 三阶段统一测试与 Review 要求

每阶段至少覆盖：

- 成功、参数校验、越权、防枚举、状态冲突、乐观锁、幂等和并发竞态。
- 领域、应用、基础设施、接口和启动配置的单元测试。
- MySQL、Redis、Elasticsearch 及应用启动集成测试。
- ArchUnit 模块边界；空间领域不得反向依赖接口、基础设施或 Spring。
- OpenAPI 每个新增字段的中文含义、可空性、限制和示例。
- 日志、指标、审计、测试报告和 Git 差异的敏感信息扫描。

每次提交前必须 Review 当前阶段完整差异。发现问题后先修复、重跑相关测试并在独立工作记录中说明问题和处理结果。不得用放宽断言、删除测试、默认管理员权限或固定 `GLOBAL` 特判掩盖空间隔离缺陷。

每阶段门禁通过后必须停止并等待用户确认；不得自动提交、推送或开始下一阶段。

## 8. 明确不在四期范围

- 多租户、租户字段、租户数据库或租户索引。
- 部门树、岗位、汇报关系、用户组同步或自动组织映射。
- LDAP、OIDC、SSO、OAuth 授权服务器或外部身份 SDK。
- 空间级共享长期记忆、自动用户画像或模型自动提升共享事实。
- 默认检索用户全部空间、跨空间联邦检索或自动知识复制。
- 空间成员查看他人工单、工单指派、支持队列或复杂工单协同。
- 每空间独立索引、独立向量数据库、新模块、新中间件或消息队列。
- 自动删除知识、自动发布案例、自动调整权限或模型决定空间。
- 延期的轻量级云服务器部署。

上述能力需要新的冻结方案和用户确认，不得作为阶段 18～20 的顺手优化。

## 9. 变更控制

以下任何变化都必须暂停实施、修订四期冻结方案和本文并取得用户确认：

- 修改 `GLOBAL` UUID、隐式读取或不可变语义。
- 修改空间角色、可见性、状态或权限包含关系。
- 修改普通检索的 `GLOBAL + 当前活动空间` 范围。
- 取消 Elasticsearch 与 MySQL 双重空间校验。
- 允许案例跨空间发布、允许空间成员查看他人工单或共享个人长期记忆。
- 修改历史数据统一迁入 `GLOBAL` 的策略。
- 新增模块、中间件、公共业务状态、身份供应商或组织架构。

普通类名、包内组织、SQL 索引细节和不改变语义的测试实现可在对应阶段自主决定，但必须经过 Review。
