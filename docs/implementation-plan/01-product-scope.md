# 产品范围与业务闭环

## 1. 产品目标

一期建设一个企业内部技术支持 Agent，优先回答已经被组织确认并发布的知识；找不到可靠知识时，引导用户显式创建工单；工单由人工解决后，再由 AI 生成待审核案例，审核发布后进入下一轮检索。

核心原则是“知识可追溯、回答有依据、写操作由人确认、AI 不凭空补全事实”。

## 2. 核心闭环

```text
用户提问
  -> 意图识别
  -> 受控知识检索
  -> 有可靠知识：带引用回答
  -> 无可靠知识：建议创建工单
  -> 用户显式确认并创建工单草稿
  -> 人工提交、处理并解决工单
  -> 异步生成案例草稿
  -> 人工修改、审核并发布
  -> 案例进入知识索引
```

检索链路发生技术故障时，不得伪装成“知识库没有答案”，也不得因此建议创建工单。

## 3. 一期能力范围

- 支持 Markdown 文件、TXT 文件和直接文本作为托管知识输入。
- 知识来源只有 `MANAGED_DOCUMENT` 和 `RESOLVED_CASE`。
- 支持多轮技术支持对话、知识引用、工单查询和明确的能力边界回复。
- 支持工单草稿、提交、解决、关闭。
- 支持解决后案例生成、人工编辑、拒绝、发布和归档。
- 支持知识文档发布、失败重试和归档。
- 支持 BM25、向量、混合检索、RRF 与重排序。
- 支持固定离线检索评估集。
- 通过 REST、SSE、OpenAPI 和 IDEA HTTP Client 完成验证。

## 4. 一期明确不做

- 前端页面。
- 登录、JWT、RBAC、多租户。
- RocketMQ 或其他消息中间件。
- MCP Server、文件系统工具、Shell 工具、SQL 工具。
- 多 Agent 编排、`HarnessAgent`。
- 长期记忆和自动会话摘要。
- 自动写工单、自动解决工单、自动发布案例。
- 复杂审批流、评论、附件、通知、SLA、指派、优先级、标签和工单重开。
- 在线评估平台和自动调参。
- Jaeger、Prometheus、Grafana 等独立观测平台。

## 5. 角色和信任边界

一期仅供本地 MVP 使用，服务端固定操作者为 `dev-operator`。不信任客户端传入的操作者请求头。领域和应用接口仍保留 `OperatorId` 概念，便于未来引入真实身份体系。

## 6. 业务状态机

### 6.1 工单

```text
DRAFT -> OPEN -> RESOLVED
   \       \
    +-------> CLOSED
```

- `DRAFT`：用户已经创建但尚未正式提交的草稿。
- `OPEN`：已经提交、等待或正在人工处理。
- `RESOLVED`：已经确认根因和有效解决方案；一期终态。
- `CLOSED`：不再继续处理且未形成解决结论；一期终态。

禁止从 `DRAFT` 直接进入 `RESOLVED`，一期不支持重新打开。

### 6.2 托管文档

```text
DRAFT -> INDEXING -> PUBLISHED -> ARCHIVED
             |
             +----> FAILED
```

- `DRAFT`：内容已保存但不可检索。
- `INDEXING`：异步生成分块、向量并写入索引。
- `PUBLISHED`：全部分块成功进入索引，可参与检索。
- `FAILED`：索引任务最终失败，可人工修改后再次发布。
- `ARCHIVED`：内容留在 MySQL 中审计，但不再参与检索。

### 6.3 已解决案例

```text
DRAFT -> PUBLISHING -> PUBLISHED -> ARCHIVED
  |           |
  v           v
REJECTED  PUBLISH_FAILED
```

- `DRAFT`：AI 生成后等待人工审核。
- `PUBLISHING`：正在异步写入知识索引。
- `PUBLISHED`：已经发布，可参与检索。
- `PUBLISH_FAILED`：发布任务最终失败，可修改后重新发布。
- `REJECTED`：人工确认不适合进入知识库；一期终态。
- `ARCHIVED`：退出检索但保留审计；一期终态。
