# Support Agent 五期 Agent 能力扩展预规划

> 状态：已记录，待详细设计；当前不可作为编码指令。
>
> 本文只确定下一期的候选方向、优先顺序和业务边界。正式实施前必须补充字段、接口、状态、权限、外部数据源、测试数据和验收指标，并经用户确认后形成可执行的冻结方案。

## 1. 规划目标

在现有知识检索、工单查询、会话记忆和安全治理基础上，让 Agent 从“回答问题”逐步扩展为“查询企业运行事实、引导故障诊断并协助工单流转”的技术支持助手。

## 2. 候选工作包

| 顺序 | 能力 | 初步范围 | 预计工作量 |
|---:|---|---|---|
| 1 | 系统状态与故障信息查询 | 只读查询服务健康、版本发布、告警、故障公告和维护窗口，并在回答中标明数据来源 | 中等 |
| 2 | 引导式故障诊断 | 通过多轮对话收集必要信息，结合知识、系统状态和只读工具生成诊断结论或升级建议 | 中高 |
| 3 | 工单协同与 SLA | 增加分派、接单、协作记录、响应/解决时限、超时提醒和升级能力 | 较大 |

建议按表中顺序实施：系统状态查询为诊断提供事实数据，诊断结果再作为工单协同和 SLA 流转的输入。

## 3. 当前边界

- 当前只形成预规划，不修改业务代码、公共接口、数据库、Agent 工具或前端页面。
- 系统状态查询优先采用只读工具；外部监控、告警或发布平台的具体选型暂不确定。
- 引导式诊断初期不得自动执行修复命令；是否引入白名单诊断动作留待详细设计。
- 工单分派、升级等写操作必须保留人工确认、权限检查和审计，不得由模型直接决定并执行。
- SLA 提醒和升级应复用现有持久化异步任务与 Transactional Outbox，不因本规划直接引入消息队列。
- 不在本期预规划中扩展多租户、复杂 RBAC、组织架构或新的模型供应商。

## 4. 正式实施前必须确认

1. 可接入的系统状态、监控、告警和发布数据源，以及本地验收数据如何构造。
2. 诊断流程的状态、追问边界、允许调用的工具及失败降级方式。
3. 工单分派、接单、协作和 SLA 的业务规则、角色权限及工作时间口径。
4. 新增数据表、接口、事件、指标、审计字段和前端交互范围。
5. 阶段拆分、迁移顺序、固定评测集、并发测试和完整验收门禁。
