## 1. 目标、范围与执行协议

一个独立补强批次，内部按本文步骤顺序实现，最终统一验收，不拆成新的产品期次。目标是检测 SSE 断连后停止后续聊天步骤、主动取消聊天模型请求、阻断重生成、清理运行状态，并兼容已完成结果重放。

不增加模块、依赖、中间件、数据库迁移、外部取消/恢复接口或 SSE 事件；不做断点续传、重连宽限窗口、后台持续生成、Agentic RAG。Judge、后台案例和独立工单草稿不改用 SSE 取消语义。仍保持完整答案校验后才能发送正文。

获得执行指令后将本批次改为进行中并新建当日实施记录；全部门禁通过才标记完成。结束后停止，不自动提交或推送。SDK 无法传播取消、需要变更依赖或公共契约时，暂停说明证据并请求决策，不能偷偷降级为只停止等待。

## 3. 内部控制对象与生命周期

在 application/chat 下实现请求级 ChatExecutionControl、ChatCancellationException 和取消原因枚举（名称可随实现做局部调整，语义不得变化）。每个 HTTP 请求独立实例；重放请求同样具有自己的发送控制，不复用原运行控制。

| 内部成员/操作 | 含义与约束 |
|---|---|
| cancelReason | 首次取消原因；无取消时为空；仅固定枚举 |
| cancel(reason) | 线程安全、幂等地记录取消并执行活动取消动作；不做数据库 I/O |
| checkCancelled() | 已取消则抛专用异常，未取消无副作用 |
| register(action) | 返回可注销句柄；已取消则立即执行 action，不能漏通知 |
| close registration | 幂等移除本次动作，不影响其他注册或请求 |
| tryEnterCommit() | 与 cancel 原子竞争，成功后进入不可取消提交区；只允许进入一次 |
| commit outcome | 区分未提交、已提交、结果未知，用于终态处理，不写为新业务状态 |

使用短锁或原子状态协调；取消回调在锁外执行，回调异常独立捕获，不能阻塞其他取消动作。最终提交区间不是长期持锁：只原子切换执行权，然后释放锁执行有超时的存储操作。

连接关闭标记与提交执行权分开：提交先获胜时仍停止网络发送，但不能把已提交结果改为失败。正常发送完成不触发取消；重放完成不能覆盖原运行审计。

## 4. 实施步骤一：SSE 生命周期与发送队列

执行状态：2026-11-02 已完成，本批次在此停止。[步骤一工作记录](../work-logs/2026-11-02-chat-sse-lifecycle-step-one.md)记录 328 项单元/接口测试、62 项集成测试与 Review。ChatExecutionControl 本步骤只实现首次取消原因标记；动作注册、模型取消、全面业务检查与提交协调按后续步骤接入。当前没有端到端停止 LLM 的保证。

1. 在异步任务启动前准备控制对象、sink 和生命周期回调，避免任务先运行、回调后注册的竞态。同步 prepare 仍保留认证与权限校验；取得运行权后如调度失败，必须终结该运行。
2. onError、onTimeout、发送失败和异常 onCompletion 通知同一控制对象；正常完成通过明确标记识别，不靠“回调发生了”推断。
3. 关闭 sink 时停止心跳、拒绝新事件、清空队列并异常完成所有未确认发送。对已取出正在发送的 PendingEvent 也要完成失败通知。
4. 通过显式唤醒/中断或可靠终止信号让 drain 退出，不能只设置 closed 后仍阻塞 queue.take。不得因队列已满而丢失关闭通知。
5. 心跳调度和任务句柄注册同样处理先关闭后注册；幂等清理仅作用于当前请求。

沿用 15 秒心跳、32 个待发事件、5 秒慢客户端保护和 5 分钟 SSE 超时，不新增调参项。心跳只是探测机会，不保证 15 秒内一定感知断网。

## 5. 实施步骤二：模型取消传播

执行状态：2026-11-02 已完成本步骤测试与 Review，停止等待步骤三指令。用户确认在现有 agent 模块通过 SDK HttpTransport 扩展补齐可取消 JDK HTTP 传输，不增加依赖。[步骤二工作记录](../work-logs/2026-11-02-chat-model-cancellation-step-two.md)保留默认 SDK 闲置流 dispose 阻塞的失败证据。实际适配器传输验证通过，不得将新传输通过解释成原默认 SDK 已修复，也不代表完整批次完成。

在 ChatModelPort 三个回答入口及 IntentRecognitionPort 增加显式控制参数。在线聊天必须调用支持取消的入口；原无取消入口如因离线评测需要保留，应明确只用于非 SSE 调用，禁止用默认方法静默丢弃在线取消参数。

在 agent 模块封装小范围的可取消流等待逻辑，复用已有 Reactor 能力，不新增 SDK：

1. 建立实际订阅时捕获取消句柄，将请求取消信号连接到该订阅及等待结果。
2. 已取消则不发请求；取消与订阅建立并发时，晚建立的订阅立即取消。取消不能仅让 Flux 正常空完成，否则可能被误判为空答案后重试。
3. 取消同时唤醒等待方，丢弃本次未完成正文；超时、正常结束和异常结束均注销动作并释放本次资源。
4. 捕获异常时优先识别专用取消，保持其语义；不得包装成 CHAT_MODEL_UNAVAILABLE，也不得让供应商/SDK自动重试取消请求。
5. 工单 Agent 取消顶层执行订阅并释放本次 Agent；每次工具入口检查取消，禁止取消后的下一次工具调用/推理。不得关闭共享模型或共享 HTTP 客户端。

首先增加本地 HTTP 验证 AgentScope Java 2.0.1 的订阅取消传播。若订阅终止但底层 HTTP 请求仍持续，应记录定位结果并在现有适配范围内补齐；需要升级或替换依赖必须先确认。

上下文组装可能含摘要生成，检索可能含 Embedding/Rerank。本批次在这些阶段前后检查取消，审计其异常包装，阻止取消后启动后续阶段；不承诺为其全部底层请求新增主动中断能力。等待这些既有同步操作时仍受其既有超时约束，不能据此宣称所有场景都能秒级清理。

## 6. 实施步骤三：业务取消与运行清理

执行状态：2026-11-02 已完成本步骤、359 项单元/接口测试、75 项集成测试与完整 Review，失败、错误及跳过均为 0。[步骤三工作记录](../work-logs/2026-11-02-chat-business-cancellation-step-three.md)记录真实 SSE → 模型 HTTP 取消 → Redis/MySQL 清理证据。当前停止在本步骤，提交门闩、提交核实、完整批次指标及重放版本/前端调整仍留给步骤四、五。

在加载上下文、意图识别、路由、检索、生成、安全校验前后，以及每次重生成、正文片段和最终提交前检查取消。取消产生后不新增输出校验、降级、模型请求或正常成功后处理。

单独捕获 ChatCancellationException：不尝试发送 error，先按当前所有者/会话/runId 释放占用，再记录失败审计；其中一项失败不能跳过另一项。记录终止原因采用冻结的 CHAT_CLIENT_DISCONNECTED、CHAT_RESPONSE_TIMEOUT、CHAT_CLIENT_TOO_SLOW；沿用现有 FAILED 终态，不新增数据库 CANCELLED 状态。

正常故障但恰好发生断连时，以首次取消原因和提交事实协调，不能重复写失败。旧运行迟到完成、清理或续租均受 runId 围栏限制。控制对象及订阅释放走 finally，不依赖成功发送 error。未开始执行即断连也必须经过同一清理路径。

取消前已开始的同步摘要等工作可能完成已有合法副作用，本批次不做跨资源回滚；不得在检测取消后继续主动开始新摘要或记忆任务。最终提交已经成功、随后连接关闭时，保留成功，跳过尚未开始的可选成功后处理。

## 7. 实施步骤四：最终提交及响应不确定

执行状态：2026-11-02 已完成本步骤、完整 Review 和全量后端门禁：369 项单元/接口测试、86 项集成测试，失败、错误、跳过均为 0。[步骤四工作记录](../work-logs/2026-11-02-chat-commit-coordination-step-four.md)记录提交门闩、代际快照、真实 Redis 原子核实及应用故障注入；未执行步骤五，完整批次指标和重放/前端兼容留待后续。

保持“安全正文发送成功后才提交完整轮次”的现有顺序。全部客户端写入及事件序号准备在提交门闩之前完成，门闩内只协调必要存储操作，不等待 SSE 写入。

| 情况 | 处理 |
|---|---|
| 取消先获胜 | 不调用 complete；清理当前运行，不递增会话版本 |
| 提交先获胜且明确成功 | 保存完整轮次，成功审计；断连不回滚 |
| 存储明确拒绝当前运行 | 不提交旧结果，按现有围栏/冲突语义结束 |
| complete 返回超时或连接异常 | 进入原子核实/终结流程，不先调用普通 fail |

在 ConversationStorePort 提供内部 resolveCommitOrFail 操作（建议名），Redis Lua 在同一次原子操作中检查指定代际消息的已完成结果及 runId：

- 同一 runId 已完成：返回已提交结果，禁止覆盖成功。
- 同一 runId 仍活动且未完成：原子标记失败并释放占用，使迟到 complete 因围栏失效被拒绝。
- 归属/代际不符、消息不存在或已有新运行：返回未拥有/不可确认，不修改新运行。
- Redis 不可访问：上层记录提交结果未知，不伪造成功或失败；原运行按租约恢复。

核实依据使用 begin 获取的内部代际快照（内部 PreparedChat/BeginResult 可增加字段，需中文说明，不向 REST/SSE 增加字段）。核实不能使用带副作用的 begin 或触发再次模型调用。Lua 原子终结用于防止“先查未提交、随后迟到提交成功、再误写失败”的竞态。

成功审计失败与会话结果失败分开处理，不能因 MySQL 审计故障抹掉 Redis 已保存结果；记录安全告警及核实结果，不新增分布式事务或后台补偿平台。未知状态不触发摘要、记忆或模型重试。

## 8. 实施步骤五：幂等重放与前端兼容

Redis begin 顺序调整为：校验会话存在性、所有者、空间与当前代际 → 校验消息内容哈希 → 命中 COMPLETED 则重放 → 新执行校验 expectedVersion → 运行互斥与租约 → 取得新 runId。

客户端持旧版本或未取得完成后的版本，仍能重放同代际已完成消息；不能绕过 reset 代际隔离，失败消息与新消息仍须版本一致。同 ID 不同内容始终拒绝。已完成重放只读原结果并分配发送事件，不写新轮次、建议、摘要或记忆；重放再次断连不能改原审计或清理其他活动运行。发送正文前仍执行权限复核。

前端检查并补齐以下行为，不扩展新页面：

- 显式重试复用 clientMessageId，清空该条临时正文/引用/建议后接收完整重放，不重复创建消息。
- 本地 abort、网络中断、缺失 answer.completed 均不表示服务端确定未提交。提示使用“连接已中断，结果状态待确认；可重新加载会话或重试”，替换当前断言未保存的取消文案。
- 无业务完成事件就结束的流不得标记成功；普通 EOF/网络中断允许用户显式重试，不自动循环请求。忙响应不自动生成新消息 ID 或高频重试。
- 刷新会话后以服务端事实为准，不把本地 IDLE 当作运行占用已清理的证明。错误恢复不得丢失正在重试的消息标识或拼接旧正文。

首次会话连 conversation.started 都未收到时无法保证找回 conversationId，保留冻结限制；不增加浏览器持久化恢复、全局消息定位或自动重连。

## 9. 可观测性与时效验收

通过现有遥测端口和 Micrometer 适配增加固定枚举能力，不新增中间件。指标建议名以代码命名规范统一，以下语义必须保持：

| 指标 | 含义 |
|---|---|
| chat cancellation count | 最终由取消结束的执行数，按三种固定原因计数；重复回调不重复计数 |
| cancellation cleanup duration | 从后端检测取消到业务清理结束的耗时，不是从用户关页面开始 |
| cancellation cleanup result | 清理成功、部分失败、提交结果未知等固定分类；不得把未知计为成功 |
| upstream cancellation result | 取消请求已发出、本地资源已释放、释放失败的技术结果，不代表供应商推理停止 |

禁止用用户、会话、runId、查询或模型输出作指标标签。取消无法获得完整 usage 时记录用量未知，不生成零 Token 断言；不为此重构其他调用既有计费报表。

本地健康环境、直接聊天模型流场景：从已检测取消到等待线程结束及会话占用释放，验收上限 5 秒；上游传输终止同样使用 5 秒有界等待验证。重复验证首 Token 前和生成中各场景，不用长 sleep 假定成功。该上限不是网络断连探测 SLA，也不覆盖正在等待既有同步依赖或持久化故障的场景；这些场景记录实测及原有超时/租约兜底。

## 10. 测试矩阵与门禁

### 10.1 不依赖网络的单元测试

- 控制器件：先取消后注册、先注册后取消、重复取消、注销与取消竞争、动作抛异常、两请求隔离、提交门闩竞争。
- 用例：未启动先取消、检索返回后取消、首 Token 前取消、校验失败后取消不重生成、意图取消不降级、正常故障仍保持既有语义。
- 清理：各项独立执行、旧运行不能清理新运行、已提交不改失败、未知不猜结果、不触发摘要/记忆后处理。
- sink：满队列关闭、阻塞 take 唤醒、已取出 PendingEvent 失败通知、正常完成不取消、重复生命周期回调。
- 前端：原消息重试、正文替换、EOF 未完成、结果未知文案、无自动重试、服务端忙与版本恢复。

### 10.2 本地 HTTP/基础设施集成测试

- 使用本地合成 OpenAI 兼容流，覆盖首 Token 前挂起和持续生成；观察订阅终止和服务端连接/流关闭，证明取消传播而非只提前返回。观察方法应适配 HTTP 协议，不能把一次写失败当作唯一证据；至少结合本地等待退出与流关闭/持续写终止，并确认无第二次请求。
- Agent 场景在工具调用与下一次推理之间取消，确认不再发请求；并行另一个请求继续完成，证明没关闭共享客户端。
- 真实 Redis Lua 验证旧版本完成重放、新执行版本检查、同 ID 内容冲突、代际隔离、取消清理、迟到提交、核实与 complete 两种先后顺序、重复终结。
- 通过故障注入模拟 complete 已执行但响应丢失，以及未执行/未知情形；Mock 只用于可控异常边界，不能替代 Redis 原子性测试。
- 启动真实后端，以真实 HTTP SSE 客户端主动断开，并以本地模型流替代供应商端，验证上游终止、审计原因、会话恢复 IDLE、相同消息显式重试成功及正常完成不受影响。测试配置只能存在于测试源集，不能在生产添加假模型入口。
- 前端 Playwright 连接真实后端，覆盖用户中止/断流后重试与已完成结果恢复；不得用请求拦截伪造后端取消成功。
