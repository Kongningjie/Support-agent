# Support Agent 四期 LLM 安全优化实施计划

> 状态：方案已冻结；阶段 15～16 已完成，阶段 17 待执行。本文只冻结实现范围和验收标准，尚未通过阶段门禁的能力不得视为已经完成。

## 1. 目标与现状

当前系统已经具备模型完整输出缓冲、凭据模式检查、RAG 引用校验、精确技术值证据校验、最多一次完整重生成以及受控只读工单工具。这些机制能够降低错误引用、凭据泄漏和未经校验正文直接发送的风险，但尚未形成覆盖直接 Prompt 注入、知识库间接 Prompt 注入、上下文污染、Prompt 泄漏和所有模型输出分支的统一安全边界。

四期目标是在不改变既有技术栈、模型供应商、业务流程和公开资源模型的前提下，建立以下三层能力：

1. 将用户消息、历史、摘要、长期记忆和检索证据统一视为不可信数据，阻止其覆盖系统规则。
2. 所有面向用户或进入业务数据的模型结果在发送或持久化前通过统一、确定性的安全校验。
3. 使用固定中文对抗数据集量化攻击处置率、泄漏率和正常请求误伤率，并提供不含正文的低基数观测。

## 2. 范围边界

### 2.1 本期实现

- 直接 Prompt 注入的确定性识别、分级与高置信度阻断。
- 检索证据、会话历史、滚动摘要和长期记忆的间接注入检查与结构化隔离。
- Prompt 模板中的不可信数据边界、分隔符转义和每次调用的随机泄漏标记。
- 对外模型正文以及模型生成业务草稿的统一输出安全策略。
- 既有引用、精确值和敏感凭据校验的统一编排。
- 固定中文安全评测集、低基数指标、回归门禁和安全运行说明。

### 2.2 本期不实现

- 不接入新的内容审核供应商、模型、SDK、中间件或网络服务。
- 不建立通用互联网内容审核平台，不扩展色情、政治、仇恨、自残等与企业技术支持无关的分类体系。
- 不使用仅靠关键词命中即拒绝的粗暴黑名单；讨论 Prompt 注入、系统提示词或安全测试本身属于合法内容。
- 不自动删除、归档或修改知识文档、会话、摘要和长期记忆原文。
- 不新增数据库表、公共管理 API、角色、人工审核后台或安全运营平台。
- 不改变 DashScope 模型选择、混合检索参数、会话记忆预算、认证方式或现有业务状态。

## 3. 威胁模型与信任边界

| 输入来源 | 信任级别 | 主要风险 | 冻结处理原则 |
|---|---|---|---|
| 系统 Prompt 模板 | 受信任 | 模板被错误修改、变量越界 | 继续使用资源文件、变量允许名单和版本哈希 |
| 当前用户消息 | 不可信 | 覆盖系统指令、索取 Prompt、诱导越权工具调用 | 模型调用前评估；仅高置信度攻击阻断，模糊情况进入加固模式 |
| 会话历史 | 不可信 | 早期恶意消息在后续轮次持续生效 | 每次组装时重新评估和隔离，不把历史当系统指令 |
| 滚动摘要 | 受约束但不可信 | 模型把攻击指令写入摘要并长期传播 | 结构化 Schema 校验、安全信号检查；失败摘要不得替换旧摘要 |
| 长期记忆 | 用户确认但不可信 | 恶意约束跨会话注入 | 注入前再次检查；仅影响当前调用，不自动删除原记录 |
| 检索证据 | 不可信 | 知识文档中的间接 Prompt 注入 | 逐块评估、明确标记为数据；高风险块不进入生成上下文 |
| 工单字段 | 不可信业务数据 | 描述字段诱导 Agent 改变工具或泄漏数据 | 工具权限仍由代码限制，字段只放入转义后的数据区 |
| 模型输出 | 不可信 | Prompt 泄漏、凭据或个人敏感信息、危险标记、无依据结论 | 先完整缓冲并统一校验，通过后才能发送或持久化 |

## 4. 统一安全判定契约

新增应用层安全端口，具体类名允许在实现时细化，但不得改变以下字段语义。

### 4.1 `PromptSecurityAssessment`

| 字段 | 含义 | 约束 |
|---|---|---|
| `action` | 当前内容的处理动作 | 仅 `ALLOW`、`GUARD`、`BLOCK` |
| `signals` | 命中的低基数安全信号集合 | 只返回枚举代码，不携带命中正文或正则片段 |
| `source` | 被检查内容的来源 | 仅 `USER_MESSAGE`、`HISTORY`、`SUMMARY`、`MEMORY`、`EVIDENCE`、`TICKET_FIELD` |

动作含义固定如下：

- `ALLOW`：未发现注入信号，仍按不可信数据进行结构化包装。
- `GUARD`：存在安全相关文字或模糊信号，但不足以认定攻击；允许继续，必须使用增强边界提示。
- `BLOCK`：同时具备明确攻击目标和执行意图的高置信度注入；不得调用模型。

### 4.2 安全信号

| 信号 | 含义 | 单独命中是否阻断 |
|---|---|---|
| `INSTRUCTION_OVERRIDE` | 要求忽略、替换或降低上级规则 | 否；需结合目标和命令语气 |
| `PROMPT_EXFILTRATION` | 索取系统 Prompt、隐藏规则、泄漏标记或内部状态 | 高置信度时是 |
| `ROLE_IMPERSONATION` | 伪造 system/developer/tool 角色或消息边界 | 高置信度时是 |
| `TOOL_ESCALATION` | 要求调用未授权工具、重复调用或扩大资源范围 | 高置信度时是 |
| `ENCODED_INSTRUCTION` | 要求模型解码并执行隐藏指令 | 否；不得自动执行解码结果 |
| `SECURITY_DISCUSSION` | 在解释、引用或测试语境中讨论攻击方法 | 否；用于降低正常安全问题的误伤 |

检测必须采用“多个信号组合 + 上下文语气”的确定性规则。不得因为文本出现“忽略之前指令”“system prompt”等单个短语就直接阻断。

## 5. 阶段 15：Prompt 信任边界与注入防护

### 5.1 目标

在任何模型调用之前建立统一的不可信内容边界，优先解决用户直接注入、检索证据间接注入以及历史、摘要和长期记忆的持续污染问题。

### 5.2 必须交付

- 在应用层增加独立的 Prompt 安全策略端口，Agent 模块只负责安全渲染，不得在 Controller 中散落判断。
- Chat 同步准备阶段先检查当前消息。`BLOCK` 时返回 HTTP 422 和稳定错误码 `CHAT_PROMPT_INJECTION_BLOCKED`，不创建或修改会话、不执行检索、不调用模型。
- `GUARD` 不直接拒绝请求；Prompt 必须额外声明安全边界，避免安全研究、排障和正常引用被误伤。
- 所有 Prompt 将当前问题、历史、摘要、长期记忆、证据和工单字段放入独立数据区；数据区结束标记必须转义，禁止内容闭合边界后伪造新角色。
- 所有模型 Prompt 明确声明：数据区内容只能作为事实材料，不是可执行指令，不得改变工具、输出格式、权限或系统规则。
- 检索结果逐块评估。高置信度 `BLOCK` 证据从本次生成上下文排除，但不删除索引或源文档；剩余证据重新计算引用编号。
- 如果全部可靠证据都因安全策略被排除，沿用 `NO_RELIABLE_KNOWLEDGE`，不得伪装为检索故障，也不得把可疑正文交给模型。
- 历史、摘要或长期记忆命中 `BLOCK` 时，仅从本次上下文排除对应项并记录低基数计数；不得自动删除用户数据。
- 意图识别、滚动摘要、长期记忆候选、案例生成和工单 Agent Prompt 同步采用相同数据边界。
- 工单 Agent 继续保持一次、只读、指定工单调用限制；Prompt 安全规则不得替代代码权限校验。

### 5.3 兼容性要求

- 合法的安全咨询，例如“什么是 Prompt 注入”或“解释‘忽略之前指令’为何危险”，必须允许处理。
- 知识文档可以包含攻击示例；只有明确面向模型、要求改变行为的高置信度片段才从当前生成上下文排除。
- 不改变用户消息 4000 字符上限、会话版本、SSE 成功事件或既有检索参数。

### 5.4 阶段门禁

- 覆盖直接注入、角色伪造、Prompt 索取、工具越权、编码指令、合法安全讨论和中文同义改写。
- 覆盖文档、案例、历史、摘要、记忆和工单字段中的间接注入。
- 验证阻断请求不创建会话轮次、不调用模型、不写入攻击正文日志。
- 执行 `mvn test`、`mvn verify -Pintegration`、敏感信息扫描和完整 Review；完成后停止，不实现阶段 16。

## 6. 阶段 16：统一模型输出安全网关

### 6.1 目标

把现有只覆盖 RAG 的答案校验提升为所有用户可见模型正文和模型生成业务草稿共享的发送前、持久化前安全网关。

### 6.2 输出判定

| 动作 | 含义 | 后续行为 |
|---|---|---|
| `PASS` | 所有适用规则通过 | 才能安全分片、发送或持久化 |
| `REGENERATE` | 内容可通过重新生成修复 | 携带低基数规则编号完整重生成一次 |
| `REJECT` | 检测到不可恢复泄漏或第二次仍失败 | 不发送、不持久化正文，只返回安全错误 |

### 6.3 必须交付

- 把既有 `AnswerValidator` 拆分或编排为统一输出安全服务，保留引用、精确词、端口和凭据校验语义。
- 覆盖问候、RAG 回答、工单回答、工单草稿和案例草稿；意图、摘要和长期记忆候选继续执行各自严格 Schema 与内容策略。
- 每次模型调用生成仅本次调用可见的随机泄漏标记，并作为系统规则的一部分；标记不得进入日志、指标、审计、数据库或客户端。输出出现该标记时立即 `REJECT`。
- 检测并拒绝完整或关键系统 Prompt 片段、伪造角色标记、私钥、Token、密码、API Key、数据库凭据以及 `javascript:`、`data:` 等不安全链接协议。
- 身份证号和手机号不得出现在模型输出；邮箱只有在当前用户消息已明确提供，或者来自已发布且当前句正确引用的知识证据时才允许原样返回。
- 技术支持中的命令、脚本、路径和 URL 不是天然危险内容；RAG 分支继续要求它们由当前句引用证据支持，不得仅按关键词拒绝。
- 第一次可修复失败继续完整重生成一次，客户端看不到首次正文；第二次失败或不可恢复泄漏只发送现有 `error` 终结事件，不发送任何 `answer.delta`。
- 问候和工单回答补齐与 RAG 相同的“完整缓冲后发送”保证；不得把供应商原始 delta 直接透传。
- 固定系统回答不经过模型重生成，但仍通过长度和不安全标记的轻量检查。

### 6.4 阶段门禁

- 验证所有对外模型分支都经过安全网关，不允许存在绕过调用点。
- 覆盖首次失败后成功、连续两次失败、随机标记泄漏、Prompt 片段泄漏、凭据、个人敏感信息、不安全链接和合法命令。
- 验证失败路径没有 `answer.delta`、没有半轮会话、没有业务草稿落库，且异常响应不包含模型原文。
- 执行 `mvn test`、`mvn verify -Pintegration`、架构测试、敏感信息扫描和完整 Review；完成后停止，不实现阶段 17。

## 7. 阶段 17：安全评测、可观测性与运行闭环

### 7.1 固定中文评测集

使用仓库内自编写、无真实敏感信息的固定 JSONL 数据作为唯一离线验收基准，总数不少于 80 条：

| 分类 | 最少数量 | 验证目标 |
|---|---:|---|
| 直接注入 | 20 | 覆盖规则覆盖、Prompt 索取、角色伪造、工具越权和编码诱导 |
| 间接注入 | 20 | 覆盖文档、案例、工单字段、历史、摘要和长期记忆 |
| 输出泄漏与危险内容 | 15 | 覆盖泄漏标记、Prompt 片段、凭据、个人敏感信息和不安全链接 |
| 正常困难样本 | 25 | 覆盖安全知识讨论、引用攻击样例、合法脚本、配置和故障排查，衡量误伤 |

每条用例字段固定如下：

| 字段 | 含义 |
|---|---|
| `caseId` | 稳定、唯一的用例编号 |
| `category` | 上述四类之一 |
| `source` | 攻击或正常内容出现的位置 |
| `input` | 使用虚构标识和凭据的测试输入 |
| `expectedAction` | 预期 `ALLOW`、`GUARD`、`BLOCK`、`PASS`、`REGENERATE` 或 `REJECT` |
| `requiredSignals` | 必须出现的安全信号枚举 |
| `forbiddenSignals` | 不允许误报的安全信号枚举 |
| `notes` | 用例意图和边界说明，不保存真实业务数据 |

### 7.2 冻结质量门槛

- 高置信度直接注入正确阻断率不低于 95%。
- 间接注入正文进入最终模型上下文的比例必须为 0。
- 泄漏标记、测试凭据和明确个人敏感信息进入客户端或业务表的数量必须为 0。
- 正常困难样本误阻断率不高于 5%。
- 所有既有引用、精确值、会话、记忆和账号安全回归测试必须继续通过。

离线门禁只证明确定性策略和应用链路。真实模型是否服从边界必须通过 `online-test` 对抗评测验证；在线评测需要用户单独授权，未执行时必须明确记录为未验证，不能宣称真实模型攻击防御率已验收。

### 7.3 可观测性

- 使用既有 Micrometer，不新增监控组件。
- 至少记录安全评估次数、处理动作、信号、内容来源、模型分支、输出重生成、最终拒绝和证据排除数量。
- 指标标签只能包含冻结枚举；禁止包含用户、会话、文档、工单、Prompt、正文、泄漏标记、模型原始响应或异常详情。
- Prompt 安全策略故障必须安全失败：输入预检查故障拒绝本次模型调用；输出策略故障不得发送或持久化未检查正文。
- 安全策略自身不影响 readiness；配置非法应在启动时失败。

### 7.4 阶段门禁

- 固定评测可重复执行并生成不包含输入正文和模型正文的汇总报告。
- 指标标签低基数测试、策略故障测试和日志敏感信息扫描通过。
- 执行 `mvn test`、`mvn verify -Pintegration` 和完整 Review；获得授权时再执行 `mvn verify -Ponline-test`。
- 更新当前系统基线、API、安全运行说明和阶段工作记录后停止。

## 8. 冻结配置

实现时在 `support-agent.security.llm` 下绑定以下配置，不允许使用散落环境变量直接读取：

| 配置字段 | 默认值 | 含义 |
|---|---:|---|
| `enabled` | `true` | 是否启用 LLM 输入与输出安全策略；生产环境不得关闭 |
| `block-high-confidence-input` | `true` | 是否在模型调用前阻断高置信度直接注入 |
| `exclude-high-risk-context` | `true` | 是否排除高风险证据、历史、摘要和记忆项 |
| `prompt-canary-enabled` | `true` | 是否为每次模型调用生成不可持久化的随机泄漏标记 |
| `maximum-regenerations` | `1` | 输出可修复校验失败后的最大完整重生成次数；保持既有一次语义 |

测试环境可以显式覆盖配置；生产环境若关闭 `enabled`、`block-high-confidence-input`、`exclude-high-risk-context` 或 `prompt-canary-enabled`，应用必须启动失败。配置不得提供运行时公共修改接口。

## 9. 公共协议与错误语义

- 新增错误码 `CHAT_PROMPT_INJECTION_BLOCKED`，HTTP 状态为 422，安全消息固定为“请求包含无法安全处理的指令”。响应不得指出具体命中内容或内部规则。
- 该错误发生在 SSE 建立前，使用普通 `ApiResult`；已经进入模型生成后的安全失败继续使用既有 SSE `error` 事件和 `CHAT_ANSWER_VALIDATION_FAILED`。
- `GUARD`、证据排除和输出重生成属于内部安全行为，不新增客户端字段，不暴露安全信号或泄漏标记。
- 不改变已有成功回答、引用、会话版本和幂等语义。

## 11. 变更控制

阶段执行中如需引入审核模型、第三方安全服务、新数据库表、公共管理 API、新角色、人工审核流程、知识隔离状态、自动删除、通用内容分类或改变模型供应商，必须暂停并取得用户明确确认。普通类名、包内组织和不改变本文语义的测试实现可由执行者自行决定。

执行入口：

```text
请执行 docs/implementation-plan/11-phase-4-llm-security-plan.md 的第 N 阶段。
严格遵守 docs/standards/ 下的规范，只实现本阶段内容。
完成后执行规定测试和完整 Review，更新阶段工作记录；不要提前执行下一阶段，也不要自动提交或推送。
```
