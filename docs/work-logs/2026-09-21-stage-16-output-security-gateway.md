## 阶段目标与验收标准

- 目标：让问候、RAG、工单回答、工单草稿和案例草稿在发送或持久化前统一执行确定性输出安全检查。
- 验收标准：覆盖可修复失败重生成、连续失败、泄漏标记、Prompt 片段、凭据、个人敏感信息、不安全协议和合法技术内容，并通过离线、集成、架构、敏感信息扫描及完整 Review。
- 不在范围：阶段 17 的固定安全评测集、安全指标、故障注入与真实模型对抗质量门禁。

## 实施记录

- 新增应用层 `ModelOutputSecurityPolicy`、确定性实现及统一服务，输出动作固定为 `PASS`、`REGENERATE`、`REJECT`，失败反馈只包含枚举规则编号。
- 问候、RAG、只读工单回答、建议工单草稿和已解决案例草稿全部在外发或持久化前接入统一网关；固定系统回答执行长度和危险标记轻量检查。
- 每次受保护生成调用使用独立 `SA-CANARY-<UUID>` 随机标记。标记只追加到系统 Prompt；工单 Agent 在启用标记时不持久化包含系统上下文风险的不透明 Agent 状态。
- 输出检查覆盖关键系统 Prompt 片段、伪造角色、私钥、Token、密码、API Key、数据库凭据、不安全链接协议、中国身份证号、手机号和受限邮箱。
- 邮箱只允许来自当前用户消息，或来自邮箱所在句正确引用的当前有效知识证据；普通命令、脚本、路径和安全 URL 不按关键词拒绝。
- RAG 继续复用引用、精确值、端口和敏感内容验证；案例草稿新增精确技术值来源约束的完整重生成语义。
- 第一次可修复失败最多完整重生成一次，并使用新的随机标记；第二次失败或不可恢复泄漏只返回安全错误，不发送失败正文，也不提交半轮会话或业务草稿。
- 生产装配新增随机标记与重生成次数配置校验；`prod` 不允许关闭任一安全开关或把重生成次数改为非 `1`。

## 文件与契约变化

- 应用层新增 `ModelInvocationSecurity` 以及 `security` 包内的输出类型、规则、动作、请求、结果、策略和服务。
- `ChatModelPort` 增加携带单次安全上下文的兼容重载；DashScope Chat 适配器把随机标记和低基数反馈追加到受信任系统指令。
- `ChatUseCase`、`SuggestedTicketUseCase`、`ResolvedCaseGenerationTaskHandler` 接入统一网关；没有新增公共 API、数据库表、业务状态、中间件或依赖。
- `application.yml` 与 `.env.example` 增加 `prompt-canary-enabled`、`maximum-regenerations`，字段含义和生产约束已同步到工程运维文档。
- API/SSE 文档明确失败路径仍使用 `CHAT_ANSWER_VALIDATION_FAILED` 和既有 `error` 事件，不暴露规则、标记或模型正文。

## 设计偏差与确认

- 无范围偏差。意图、滚动摘要和长期记忆候选继续使用各自严格 Schema 与内容策略，没有纳入面向用户正文网关。
- 建议工单的邮箱授权从冻结建议上下文中的最后一个“用户当前问题”提取；历史轮次中的邮箱不会因此获得原样返回授权。
- 阶段 17 的固定对抗数据集、指标和真实模型对抗质量门禁未提前实现。

## Review 记录

- Review 范围：阶段 16 新增和修改的应用层安全策略、全部 Chat 模型调用点、DashScope 系统 Prompt 注入、Spring 装配、配置、测试及文档；同时核对当前工作区完整差异，未覆盖或回滚阶段 14～15 的既有未提交变更。
- 首轮发现并修复：Mockito 旧重载导致测试未命中新调用；案例结构化模型异常和新增精确值未执行一次完整重生成；结构化空字段可能被字符串 `null` 绕过；建议工单误把全部历史上下文作为邮箱授权来源；证据标题中的邮箱未纳入引用授权；配置示例注释仍只描述三个开关。
- 修复后重新检查所有受保护模型调用点：生产装配均使用统一服务；随机标记不进入日志、指标、审计、数据库和客户端；失败异常不包含模型正文；草稿保存只发生在安全检查通过后。
- `git diff --check` 无空白错误，仅报告 Windows 工作区既有 LF/CRLF 转换提示。
- Review 结论：通过，未发现尚未闭环的阶段 16 阻断问题。

- `mvn test`：通过，共 235 个测试，0 失败、0 错误、0 跳过；包含 Domain 与 Bootstrap ArchUnit 架构测试。
