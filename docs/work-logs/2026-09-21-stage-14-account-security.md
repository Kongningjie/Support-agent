## 阶段目标与验收标准

- 目标：补齐本地账号改密、管理员重置与解锁、递增登录锁定、Token 数量治理、角色和状态管理、安全审计及未来外部认证端口边界。
- 验收标准：公共接口、MySQL/Redis 原子行为、受限 Token、越权防护、审计与低基数指标均有自动化验证，并通过 `mvn test`、`mvn verify -Pintegration`、敏感信息扫描和完整 Review。
- 不在范围：组织架构、多租户、复杂 RBAC、第三方登录页面、OAuth 授权服务器、真实 OIDC/SSO 联调或新的身份 SDK。

## 已完成工作

- 扩展本地用户安全状态，新增 `mustChangePassword`、`lockedUntil`、角色变更、本人改密、管理员一次性密码重置和解锁规则。
- 使用 Redis Lua 原子实现用户名与来源维度的渐进退避：第 3、4、5 次及以上失败分别锁定 30 秒、2 分钟和 15 分钟；账号锁截止时间使用 MySQL 单调延长更新，避免并发版本冲突。
- 为强制改密登录签发受限 Token，仅允许本人查询、改密和注销；改密后撤销全部旧 Token 并要求重新登录。
- 保持 Token TTL 为 2 小时，使用 Redis ZSET 原子限制每用户最多 5 个有效 Token，并兼容迁移阶段 11 的 Set 索引。
- 增加用户分页、角色变更、管理员密码重置、解锁和 Token 全量撤销接口，并补齐统一错误状态和 HTTP 示例。
- 新增最小化 `security_event` 审计表和低基数 Micrometer 指标；事件不保存用户名、密码、原始或哈希 Token、请求正文。
- 引入稳定 `AuthenticationPort`、本地适配器、外部主体和关联端口；未接入真实 OIDC/SSO 或新身份 SDK。

## 设计偏差与确认

| 偏差 | 原因 | 确认情况 | 影响 |
|---|---|---|---|
| 管理解锁只清理用户名维度计数 | 来源计数可能由多个用户共享，按用户解锁时无法安全批量删除 | 已在冻结方案中明确 | 防止管理员解锁一个账号时绕过共享来源保护；登录成功仍同时清理两类计数 |
| 不执行真实在线模型测试 | 本阶段不修改或调用模型链路 | 不需要额外授权 | 不影响账号安全验收，不据此声明模型质量 |

## 风险、限制与未完成项

- 风险：Redis 限流与 Token 上限按单实例共享 Redis 原子生效；若未来拆分认证域或引入外部身份提供商，必须重新评审主体映射、审计事务和令牌治理。
- 限制：本阶段仅定义外部认证边界，不接入真实外部身份提供商；管理员解锁不会清除共享客户端来源计数。
- 已知非阻断项：应用启动测试仍会输出既有 Springdoc `JsonSchema.type` 兼容警告，但 OpenAPI 请求和启动集成测试通过；该告警并非阶段 14 引入。
- 未完成项：无。
