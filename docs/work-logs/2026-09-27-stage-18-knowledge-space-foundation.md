## 目标与范围

- 建立知识空间、成员关系和统一空间访问判定的领域与应用边界。
- 通过 Flyway V9 创建空间表、迁移历史文档、工单和案例到固定 `GLOBAL` 空间，并扩展安全审计资源标识。
- 实现空间与成员治理 API、幂等、乐观锁、防枚举、审计、OpenAPI 和 HTTP 示例。
- 为既有资源补充 `spaceId` 与最小空间摘要，同时保持现有 Chat 和检索语义不变。
- 本阶段不修改 Elasticsearch Mapping、BM25/向量查询、Redis 会话空间绑定，也不允许非 `GLOBAL` 资源写入。

## 开始状态

- 当前分支为 `main`。
- 工作区包含用户尚未提交的四期文档重组与冻结方案变更；实施过程中必须完整保留，不覆盖或回退。
- 前端 F4～F5 按用户要求暂停，阶段 18 仅实施后端范围。

## 实施、测试与 Review

### 已完成实现

- 新增知识空间、成员关系、空间角色、可见性与启停状态领域模型，固定 `GLOBAL` UUID 为 `00000000-0000-0000-0000-000000000001`。
- 新增空间访问判定和治理用例，覆盖查询、创建、修改、启停、成员授权/变更/撤权，并实现幂等、乐观锁、防枚举和最后一位受限空间管理员保护。
- 新增 Flyway V9，创建 `knowledge_space` 与 `user_space_membership`，为文档、工单、案例补充必填 `space_id`，将历史数据回填到 `GLOBAL`，并把活动文档内容唯一性改为空间内唯一。
- 空间与成员变更均写入安全审计事件；审计表新增资源类型与资源 ID，但不将高基数 ID 放入 Micrometer 标签。
- 新增 8 组空间 REST 路径及 HTTP 请求示例；文档、工单、案例响应补充顶层 `spaceId` 和最小空间摘要。
- 既有创建路径在应用层显式归入 `GLOBAL`，未增加数据库隐式默认值；未修改 Elasticsearch、BM25/向量检索或 Redis 会话语义。

### Review 发现与处理

1. 首次集成回归发现旧模式测试的表数断言和原始插入语句未包含 `space_id`。已更新断言，并在测试数据中显式写入 `GLOBAL`；未通过数据库默认值规避问题。
2. 响应契约 Review 发现仅返回空间摘要会让调用方难以直接读取固定归属标识。已统一调整为顶层 `spaceId` 加最小 `space` 摘要，并补充契约测试。
3. 停用空间的成员历史查询与写操作权限最初共用同一检查。已拆分为允许管理员查看元数据/历史、但拒绝停用空间写入，并增加回归覆盖。
4. 成员增改和撤销最初先查询目标账号、再校验空间权限，无权调用者可能借错误码推断账号是否存在。已调整为先执行空间防枚举授权，通过后才查询目标账号，并增加回归测试。
5. 完整差异复核未发现未处理的阻断问题；修复后重新执行单元与集成门禁，均通过。
6. Review 后首次重跑集成门禁时 Docker Desktop 引擎未运行，Testcontainers 因无法连接 Docker 而失败；启动 Docker Desktop 后原命令完整重跑并通过，该次失败确认为环境问题，不是业务断言失败。
