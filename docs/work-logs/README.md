# 阶段工作记录

本目录记录每个可独立验收阶段的目标、实际变更、Review、测试和遗留风险。记录用于恢复上下文和追踪决策，不替代 Git 提交历史或实施设计。

## 命名规则

文件名使用 `YYYY-MM-DD-<phase-name>.md`，例如：

```text
2026-09-03-project-skeleton.md
2026-09-03-document-governance.md
```

同一天存在同名阶段时，在阶段名后增加两位序号。阶段名称使用小写英文和连字符，避免使用“杂项”“临时”等无明确范围的名称。

## 记录时机

- 开始阶段时复制 [阶段记录模板](TEMPLATE.md)，填写目标和验收标准。
- 实施中持续记录设计偏差、重要判断及用户确认，不在结束时凭记忆补写。
- 阶段结束时补齐文件变化、Review、测试、风险、未完成项和下一步。
- 每次提交前必须先更新对应记录，并满足 `../standards/05-testing-and-quality-gates.md` 的提交门禁。

## 记录原则

- 只记录实际发生的工作，不把计划写成已完成结果。
- 测试必须写出可复现命令、结果和执行环境；未运行时说明原因与影响。
- 每个新增或变化的字段、配置、状态、错误码和接口必须写明其含义，禁止只罗列名称。
- Review 记录必须包含范围、结论、问题和处理结果，不得只写“已 Review”。
