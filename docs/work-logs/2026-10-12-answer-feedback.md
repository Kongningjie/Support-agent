## 开始状态与目标

- `main` 与 `origin/main` 一致，开始时工作区无未提交改动。
- 用户已确认：只评价本人已成功回答，关联 `runId`；有帮助/无帮助、原因与可选 300 字说明；每轮一条，可更正删除；管理员只见聚合；MySQL 保存、不保存回答正文、不自动影响模型或知识；后端和聊天前端一并实现。
- 本批次不进入人工评测或 LLM-as-Judge，不调用在线模型。

## 实施与设计判断

- 新增独立冻结方案、单批次实施计划、MySQL V10 迁移、应用反馈用例/端口、MyBatis 适配、本人反馈 API 与管理员匿名聚合 API；会话详情公开每轮 `runId`，聊天页完成真实 REST 交互。
- `runId` 关联 `agent_run`，应用层只接受当前认证用户且运行状态 `SUCCEEDED` 的回答；他人、失败或不存在运行统一 404。
- `rating` 为帮助程度；`reason` 仅在无帮助时必填；`note` 为最多 300 个 Unicode 字符的可选说明。说明复用敏感文本策略，拒绝疑似凭据和个人信息；反馈不进入模型、检索、知识发布或指标标签。
- 首次创建版本为 0，更正要求 `expectedVersion`。Review 发现物理删除再重建会发生版本 ABA：已改为删除时立即清空评分、原因和说明，仅保留不可见版本标记；重建版本继续递增。管理员聚合排除已删除行。
- 真实 MySQL 首次集成运行发现 V10 `CHECK CASE` 不被 MySQL 8.4 接受，已拆成两条布尔约束；相关失败和修复重跑结果见下节。

- Review 范围：全部后端应用/接口/持久化/迁移差异、聊天 `runId` 传播及 SSE 完成顺序、前端 API/Store/页面、测试、HTTP 示例、冻结方案和文档；检查权限归属、成功状态、乐观锁、删除隐私、敏感文本、管理员仅聚合、无额外依赖和密钥泄露。`git diff --check` 无空白错误；仅有 Windows 换行转换提示。
