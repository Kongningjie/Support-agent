## 阶段目标与边界

- 实现默认关闭、由用户显式启用的跨会话结构化长期记忆。
- 模型只生成 `PROPOSED` 候选，只有用户确认后的 `ACTIVE` 记忆可以注入模型上下文。
- 提供本人记忆开关、列表、确认、更正、撤销和永久删除接口。
- 使用 MySQL 保存设置与记忆，不引入向量库、Elasticsearch 记忆索引或用户画像推断。
- 不实现阶段 14 的改密、锁定、令牌治理或 SSO 边界。

## 已确认补充决策

- 聊天成功提交后异步生成候选；失败不影响聊天且不自动重试。
- 使用独立 `UserMemoryCandidatePort` 和 `qwen3.7-flash`。
- 单条正文最多 500 字符，每用户最多 100 条，单次注入预算为估算 1,000 Token。
- 注入优先级为固定记忆、约束、环境、偏好、最近更新时间。
- 设置与全部写操作使用乐观锁，公共写接口同时要求 `Idempotency-Key`。
- 来源轮次使用 `clientMessageId`，不保存完整会话、回答或 Prompt。

## 实施、测试与 Review

### 实际变更

- 新增 `user_memory_settings` 与 `user_memory` 的 V6 Flyway 迁移、MyBatis 映射和仓库实现。候选数量检查与插入通过设置行 `FOR UPDATE` 串行化，确保关闭开关和每用户 100 条上限在并发下仍有效。
- 新增 `UserMemory` 聚合及 `PROPOSED`、`ACTIVE`、`REVOKED` 生命周期；确认、更正、撤销、删除均校验所有者、预期版本和幂等键。
- 新增候选专用 `UserMemoryCandidatePort`，使用 `qwen3.7-flash`、严格 JSON Schema、最多三个候选和独立虚拟线程执行器。候选生成失败不影响已经提交的聊天，也不自动重试。
- 新增正文 NFC 规范化、500 Unicode 字符上限、标准 SHA-256 去重和凭据、手机号、身份证号、邮箱、危险控制字符门禁。
- 新增本人开关、分页列表、确认、更正、撤销和永久删除接口；DTO 对 `expiresAt`、`clearExpiresAt`、`pinned`、`expectedVersion` 的空值语义分别定义。
- 已确认且未过期的记忆按 `pinned > CONSTRAINT > ENVIRONMENT > PREFERENCE > updatedAt` 选择，在独立 1,000 Token 上限内先于单会话摘要和最近轮次注入；当前问题和检索证据预算优先级不变。
- 新增 `http/26-user-memories.http` 请求示例，并更新 HTTP 索引、配置和 OpenAPI 启动验收。
