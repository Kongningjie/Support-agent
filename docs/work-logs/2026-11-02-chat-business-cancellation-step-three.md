## 测试与 Review

新增 18 项业务取消边界单元回归、1 项 MVC 无二次响应回归、1 项真实 Redis 旧运行围栏回归及 1 项真实后端断连到上游 HTTP 关闭和存储清理的集成验证。全部门禁在最终代码修正后执行完成。

验证中出现的问题与处理：

1. 新单元测试首次编译缺少 ModelInvocationSecurity 导入，并把 ModelOutputRule 写成字符串；修正测试类型。检索取消测试的 accessContext 为空导致未命中测试桩，补齐真实形态的空间上下文后通过。没有修改生产权限校验以适配测试。
2. 首次 Maven 定向命令未引用含点号的属性，被 PowerShell 拆分，未执行测试；改为 `'-Dfailsafe.failIfNoSpecifiedTests=false'`。
3. 真实 SSE 测试读取固定 256 字节导致响应头截断，改为按 HTTP 空行读取完整头部，不扩大网络超时。第二次定向验证的 SQL 使用字符串查询 BINARY(16) UUID 导致错误判为空记录，改用 UUID_TO_BIN/BIN_TO_UUID，与实际持久化一致。
4. 真实断连暴露全局异常处理器尝试把 ApiResult 写入已不可用的 SSE，产生二次转换告警。增加仅处理 AsyncRequestNotUsableException 的无正文处理，不修改正常 REST 错误映射。新增 MockMvc 回归验证已提交响应、异常被正确解析、无响应正文且不改成 500；补齐 checked exception 声明。测试最初假定异常处理会保留 Content-Type，实际 MVC 会清除该元数据；该断言不属于断连后的产品保证，改为检查无二次输出和无 500，保留真实链路的响应头断言。

真实集成链路使用临时 MySQL 8.4.11、Redis 7.4.7、真实登录和 Tomcat SSE。测试只替换聊天端口的地址选择与取消观测，内部仍调用实际 DashScopeChatModelAdapter 和本地原始 HTTP socket；不是只模拟 useCase 返回成功。观测供应商侧 socket EOF、同一次模型调用、FAILED 原因、Redis IDLE/活动运行字段清除、轮次/版本不增加及相同消息可重新取得运行权。网络检测依赖实际发送或既有 15 秒心跳，五秒门槛从服务端收到取消通知开始，不从用户关闭窗口计时。
