## 实施与验证

前端详细记录见[步骤五前端记录](../frontend/work-logs/2026-11-02-chat-replay-step-five.md)。

- Redis begin 在完成所有者、空间和消息内容校验后，先读取当前代际已完成结果，再对新执行检查版本。旧版本或未提供版本可以重放；新消息、失败消息仍严格检查版本。同 ID 不同内容、跨用户/空间和重置代际不能绕过校验。
- 重放发送前重新校验权限，不调用模型，不新增轮次、建议、审计、摘要或记忆，不释放其他活动运行。
- 前端明确显示结果待确认；仅用户显式操作重试，复用原消息 ID 并清除临时正文、引用和建议。忙响应不自动重试，版本恢复保留原消息；重置后禁用旧代际重试。读取已保存轮次时按 runId 合并，重放旧轮次不能降低当前会话版本。
- 请求控制对象记录首次取消的时间和业务阶段；一次收尾只报告一次，指标故障不阻断业务清理。未启动路径沿用真实取消时间，普通调度失败不冒充取消。

## 指标说明

| 指标 | 含义与标签 |
|---|---|
| `support.agent.chat.cancellation` | 最终取消执行数，固定 reason/stage；明确已提交、未知、未拥有和重放停止不计入 |
| `support.agent.chat.cancellation.cleanup` | 检测取消到业务收尾耗时；reason/stage/result 均为固定枚举 |
| `support.agent.chat.upstream.cancellation` | 按 result 记录 REQUESTED、LOCAL_RELEASED、RELEASE_FAILED 技术动作次数 |
| `support.agent.chat.cancelled.usage.unknown` | 上游取消时完整用量未知次数，不生成零 Token 用量 |

清理分类：RELEASED 表示围栏释放及审计调用已返回，PARTIAL_FAILURE 表示至少一项清理失败，COMMITTED 表示结果已提交，UNKNOWN 表示无法核实，NOT_OWNED 表示运行权不属于本请求，REPLAY_STOPPED 表示只停止重放。LOCAL_RELEASED 只说明本地取消调用返回或无活动资源，不保证供应商停止推理/计费。无用户、会话、runId、正文等高基数标签。
