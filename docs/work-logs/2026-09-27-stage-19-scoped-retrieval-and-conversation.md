## 目标与范围

- 让文档、工单、案例、Redis 会话和 Elasticsearch 分块形成完整空间链路。
- 让 BM25、向量召回与 MySQL 来源回查统一执行 `GLOBAL + 当前活动空间` 双重过滤。
- 让 Chat、引用、工单建议、异步任务和评测入口遵守空间访问上下文。
- 完成新版本索引的全量重建、完整性验证和原子别名切换能力。
- 本阶段不实施阶段 20 的固定 60 条隔离评测、最终兼容收口、完整治理观测或前端空间选择。

## 实施、测试与 Review

### 已完成实现

- 文档、工单、案例的创建、详情、列表和命令链路统一携带真实 `spaceId` 与最小空间摘要；文档按 `EDITOR/MANAGER`、案例按继承工单空间与 `EDITOR/MANAGER`、工单按本人或平台管理员边界执行应用层授权。
- 知识、案例及其知识异步任务 URL 改为认证后进入应用层授权；`CASE_GENERATION` 原始工单事实仍仅平台管理员可见和可重试，幂等重放也会重新鉴权。
- Redis 会话 Hash 与 Lua 脚本加入代际级 `spaceId`：历史无字段会话原子回填 `GLOBAL`，同代际换空间返回 `CHAT_SPACE_MISMATCH`，重置新代际可换空间并清理旧摘要、轮次、建议和消息状态。
- 修复元数据读取传入零条历史时 `LRANGE -0 -1` 意外加载全部轮次的问题；零限制现在不会读取历史正文。
- Elasticsearch v2 严格 Mapping 加入非空 `spaceId: keyword`；BM25 `bool.filter` 与向量 `knn.filter` 使用同一最小允许集合，解析层再次剔除缺失、非法或越界空间命中。
- 新增从 MySQL 当前已发布文档和案例执行生产分块、Embedding、Bulk 写入、逐来源版本/哈希/空间/分块数、总分块数及已知空间核对的全量重建用例；仅全部通过后原子切换别名，旧索引保留。
- MySQL 来源回查同时校验来源发布状态、版本、真实空间、活动空间状态和本次允许集合；索引与回查拒绝使用固定原因和数量记录低基数诊断，不输出空间 ID 或知识正文。
- 知识索引任务与案例索引任务执行前重读聚合和空间状态；空间停用时清理当前版本分块并以 `KNOWLEDGE_SPACE_DISABLED` 稳定原因取消，不进入重试。
- Chat 在意图和模型调用前确定会话空间并重新验证当前权限；检索评测传递完整 `RetrievalAccessContext`，允许集合严格等于 `GLOBAL + 活动空间`，不得附带第三空间。
- 引用增加并复核 `spaceId`；工单建议冻结会话空间，消费建议和写入工单前均再次校验活动空间读取权限，忽略客户端伪造空间。
- 补齐接口请求示例、错误映射、新增字段含义和历史 `GLOBAL` 兼容入口；未改变 RRF、Rerank、可靠阈值、输入安全、输出安全和个人长期记忆边界。

### Review 发现与处理

- 发现全量重建原先只要求目标分块数不少于预期，已改为总数严格相等，避免目标索引混入额外分块后仍切换别名。
- 发现人工重试命中幂等结果时可能跳过当前角色复核，已在重放路径重新校验关联资源、空间和角色。
- 发现既有会话显式空间不一致的判定晚于部分处理，已前置到权限、模型与新轮次之前。
- 发现消费工单建议只依赖后续写命令校验，已在调用草稿模型前独立复核建议冻结空间，避免无权限时消耗模型。
- 发现 Redis `recentTurnLimit=0` 会因 Lua 的 `-0` 语义读取全部轮次，已显式跳过 `LRANGE` 并增加真实 Redis 回归测试。
- 发现评测内部只传 `Set<UUID>`，已改为传递完整 `RetrievalAccessContext`；上下文构造器拒绝任何第三空间。
- 发现历史引用缺少空间字段可能无法反序列化，已按冻结兼容策略固定回填 `GLOBAL`。
- 发现取消原因可能超过数据库字段限制，已在持久化适配器按既有字段上限安全截断。
- 发现 Docker Desktop 在一次复验前临时断开，首次复验因此有 7 个容器测试在启动前报环境错误；重新启动 Docker Desktop 后原命令完整通过，未把环境失败计为通过。
- `git diff --check` 无空白错误，仅有 Windows 工作区 LF/CRLF 转换提示；SpringDoc/Jackson 启动警告为既有依赖兼容警告，不影响本阶段测试结论。
