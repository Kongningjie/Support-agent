# 聊天断连取消步骤一：SSE 生命周期与发送队列

日期：2026-11-02。状态：步骤一已完成；整体批次仍进行中。依据：[单批次计划步骤一](../implementation-plan/18-chat-disconnect-cancellation-implementation-plan.md)。用户仅授权步骤一，不执行模型订阅取消、全面业务取消、提交核实、重放顺序或前端改造。

## 目标与边界

先准备请求控制、发送通道和生命周期回调，再调度异步工作；终止通道时清理心跳、队列及发送线程，立即通知待确认事件失败；任务未启动或调度失败时释放已取得的运行占用。保留认证、权限、现有参数与 SSE 公共契约。

开始时工作区已有 2026-10-17/30 的方案及索引未提交变更，保留这些内容。步骤一仅建立实际被连接层使用的取消标记；模型订阅、重生成和生成中业务清理仍待后续步骤，不编写后续占位实现。

## 已完成工作与文件变化

| 对象 | 变化及含义 |
|---|---|
| application/chat/ChatExecutionControl | 单请求首次取消标记；三类固定原因分别表示断连、响应超时、慢客户端，不包含框架类型或模型停止保证 |
| interfaces/chat/ChatController | 同步 prepare 保留；先注册完成/错误/超时回调再调度发送、心跳、业务；调度失败和任务开始前取消分别清理未启动运行 |
| interfaces/chat/BoundedSseSink | 从控制器内提取包内可测实现；有界队列加锁协调关闭和入队，跟踪所有未确认事件，包含已出队正在写入的事件；关闭时通知失败并唤醒生产/发送线程 |
| application/chat/ChatUseCase.failBeforeStart | 仅供从未进入 stream 的唯一处理路径调用；释放当前 runId 占用并独立尝试失败审计，REPLAY 直接返回，不触碰原结果 |
| 测试 | 新增控制对象、未启动运行、sink 和控制器生命周期共 22 项单元测试；新增真实 Tomcat/MVC/SSE 传输 2 项 IT |
| 文档 | 同步计划进度、索引、当前系统基线、应用层和接口层 README，明确只完成步骤一 |

32 个待发事件、五秒慢客户端保护、15 秒心跳和五分钟 SSE 生命周期保持不变。正常完成使用队列外终止意图，队列满也不会丢失；只有真正排空并正常结束才标记正常完成。异常关闭记录首次原因，重复回调不重复清理；晚注册的发送任务和心跳句柄也会立即停止。

业务任务不直接 future.cancel：否则任务可能从未运行，无法释放 prepare 已取得的占用。已接受的业务任务仍由入口检查取消并执行未启动清理；已开始运行的流程由原用例处理发送失败，主动模型取消和全面业务检查不提前实现。连接回调不执行数据库 I/O。

Review 修正及复查：

- 调度失败不能因主动关闭 sink 被误记为客户端断连，先保存原原因，无取消时沿用 COMMON_INTERNAL_ERROR；补齐三处调度拒绝回归测试。
- 资源停止动作逐个独立尝试，单个失败不能跳过剩余资源；安全告警不输出异常正文。
- 本地通道关闭不等于所有资源确已释放，修正完成失败日志，避免夸大清理结果。
- 并发测试先确认线程已经进入等待，再触发关闭，避免把任务尚未启动误算作成功唤醒。
- 拒绝增加模型适配、提交门闩和重放顺序的提前实现，原有成功提交和生成中断连限制如实保留。

修正后相关模块重新验证通过，本步骤无已知剩余阻断问题；后续步骤未完成不冒称整体门禁通过。

## 风险、限制与后续

- 正在模型生成中的请求仍可能继续执行或重生成；本步骤没有将标记连接到模型订阅，也没有承诺上游 HTTP 关闭或供应商停止计费。
