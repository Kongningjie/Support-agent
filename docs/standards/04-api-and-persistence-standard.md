# 接口与持久化规范

## 接口契约

- 普通 JSON 接口统一返回 `ApiResult<T>`；SSE 使用独立事件协议，不包装为 `ApiResult`。
- HTTP 状态码必须反映真实结果，不得所有响应都返回 200。
- 每个请求、响应、事件和配置字段必须说明中文含义、类型、是否必填/可空、取值限制和示例，避免只列字段名造成歧义。
- 公共字段、错误码、状态和事件名称一旦发布不得随意修改；变化前必须评估兼容性并获得确认。
- Controller 只负责协议适配、校验和调用应用用例，不得直接操作 Mapper、Redis、Elasticsearch 或模型客户端。
- 外部输入必须校验；错误响应不得泄露堆栈、SQL、密钥、内部路径或模型内部信息。

## MySQL 与 MyBatis

- 使用 MyBatis XML 编写 SQL，显式列出字段，禁止 `SELECT *`。
- 更新和状态迁移必须检查影响行数；并发写入采用已确认的幂等键、唯一约束或乐观锁策略。
- 事务保持短小，事务内不得调用模型、外部 HTTP 或执行不可控的长耗时操作。
- Flyway 迁移只追加不回改；表、字段、索引必须有清晰中文含义说明，不使用数据库级联删除。

## Elasticsearch 与 Redis

- Elasticsearch 索引结构必须版本化；BM25、向量召回、RRF 和 Rerank 各阶段保持可观测、可测试。
- Redis Key 必须包含统一业务前缀、资源标识和用途；临时数据必须定义 TTL。
- MySQL 是关键业务事实的最终来源，缓存或索引失败通过 Outbox/异步任务恢复，不得静默丢失。
