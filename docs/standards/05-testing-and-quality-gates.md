# 测试、Review 与质量门禁

## 测试要求

- 每个可独立验收的阶段完成后必须执行测试，最低要求为 `mvn test`。
- 基础设施联调使用 `mvn verify -Pintegration`；真实 DashScope 验证使用 `mvn verify -Ponline-test`，且必须获得密钥与网络授权。
- 单元测试命名为 `*Test`，集成测试命名为 `*IT`。单元测试不得依赖 Docker、网络或真实密钥。
- 覆盖成功路径、参数校验、异常分支、边界值、状态迁移和幂等/并发行为；缺陷修复必须补充回归测试。
- 不得通过删除测试、削弱断言、扩大忽略范围或滥用 Mock 让测试“通过”。未执行的测试必须记录原因和风险。

## 提交前强制 Review

每次 `git commit` 前必须 Review 本次完整差异。未 Review、Review 未通过或问题尚未处理完毕时，严禁提交。

Review 至少检查：

1. 是否超出已确认的业务范围、技术栈或公共契约。
2. 模块职责、依赖方向、事务、一致性及并发处理是否正确。
3. 字段含义、异常处理、安全边界和日志内容是否清晰。
4. 类与方法注释是否完整且与实现一致。
5. 测试是否充分、实际执行并覆盖本次风险。
6. 是否包含无关改动、敏感信息、调试代码、占位实现或遗留 TODO。

发现问题必须先修复，再重新 Review 受影响内容并执行相关测试。

## 提交门禁

只有同时满足以下条件才允许提交：

- Review 已通过且发现的问题已闭环。
- 必要测试已通过，或不可执行项已明确获得接受。
- `docs/work-logs/` 中的阶段记录已更新，包含 Review 和测试结果。

编译成功或测试通过不能替代 Review。推送前还必须核对提交内容、提交信息和目标 `main` 分支。
