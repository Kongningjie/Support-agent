# Java 编码规范

## 格式与命名

- 文件使用 UTF-8；Java/XML 缩进四个空格，YAML 缩进两个空格。
- 类型使用 `UpperCamelCase`，变量和方法使用 `lowerCamelCase`，常量使用 `UPPER_SNAKE_CASE`。
- 名称必须表达业务含义，避免 `data`、`info`、`handle`、`process` 等缺少上下文的宽泛命名。
- 方法保持单一职责；存在多段独立判断或副作用时，应拆分为可命名、可测试的方法。

## 注释要求

- 每个手写类、接口、枚举和注解都必须有 Javadoc，说明职责、边界和使用约束。
- 每个手写方法（包括 `private` 方法）都必须有 Javadoc；参数、返回值或异常存在歧义时必须补充 `@param`、`@return`、`@throws`。
- 注释应解释“为什么”“有什么约束”，不得逐句翻译代码或保留过期描述。
- 编译器生成的方法、Record 自动访问器及框架生成代码可免除逐方法注释。

## 实现习惯

- 使用构造器注入；不得使用字段注入。
- 优先不可变对象和显式工厂方法，不得通过任意 Setter 破坏领域状态。
- 禁止魔法数字和字符串；稳定集合使用枚举，但不得持久化枚举 `ordinal`。
- 集合返回空集合而不是 `null`；对可空值明确约束，不得依赖隐含约定。
- 使用 `Instant` 表示系统时间，时区转换只发生在系统边界。
- 不吞掉异常，不用异常代替正常分支；资源必须使用 try-with-resources 管理。
- 一期默认不引入 Lombok。确需引入时必须先说明收益和生成代码影响并获得确认。
