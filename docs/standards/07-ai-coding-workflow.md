# AI Coding 工作流

## 开始阶段前

1. 阅读 `../implementation-plan/README.md`、本目录规范和最近一份 `../work-logs/` 记录。
2. 检查当前分支、工作区状态和已有用户改动，不覆盖或回滚无关内容。
3. 明确本阶段目标、验收条件、允许修改范围和需要执行的测试。

## 实施过程中

- 只实现当前阶段，不进行“顺手重构”、预留式抽象或未经要求的功能扩展。
- 不得自行增加技术栈、模块、接口、字段、状态、中间件或业务流程。
- 一般实现细节可在既定边界内自主决定；涉及公共契约、架构和业务语义时必须先询问。
- 使用小而聚焦的变更；不得留下伪实现、静默降级、无责任人的 TODO 或虚假测试结果。
- 不执行破坏性 Git 操作，不自动提交或推送，除非用户明确要求。

## 阶段完成检查

1. 检查完整差异和未跟踪文件，确认没有敏感信息或无关修改。
2. 执行与风险匹配的测试，记录命令、结果和未验证项。
3. 按 `05-testing-and-quality-gates.md` 完成提交前 Review 并修复问题。
4. 更新 `../work-logs/`，准确记录完成内容、文件变化、偏差、风险和下一步。
5. 只有 Review、测试和记录三项门禁均满足后，才可在用户授权下提交。

## 汇报要求

汇报必须区分“已实现”“已验证”“未验证”和“未完成”。不得把计划当结果、把静态检查当运行测试，或因环境受限而宣称任务完成。设计发生变化时，应先更新设计记录，再修改实现。
